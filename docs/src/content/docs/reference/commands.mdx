This page lists every command Iguana understands, with its arguments and its replies.

## Running a command

A command can be run in two ways:

- **From a shortcut.** The right-hand side of an entry in
  [`[bindings]`](/reference/configuration/#bindings) or in a
  [`[mode.NAME]`](/reference/configuration/#modename) table is a command.
- **From a terminal.** Put `iguana` in front of it: `iguana focus left`. See
  [Command line](/reference/command-line/).

Commands are written in lower case, with single words separated by spaces. Upper case is
accepted and treated as lower case.

### Replies

Every command answers with one line, or with a report. [`subscribe`](#subscribe) is the one
exception: it goes on printing a line for each event until Iguana quits.

- `ok` means the command did what it says.
- `ok: …` means there was nothing to do, and says why. For example `ok: nothing in that direction`.
- `error: …` means the command could not run, and says why.

In a terminal the reply is printed. For a shortcut, the last reply is shown by
[`status`](#status), and replies that start with `error` are written to the log.

### Chains

One shortcut or one line can run several commands. Put `;` between them:

```text
COMMAND; COMMAND ...
```

```toml title="iguana.toml"
[bindings]
option-shift-r = "flip; balance"
```

```sh
iguana "flip; balance"
```

- **The commands run in order,** each as if it were run alone.
- **The first error stops the chain.** That error is the reply. Otherwise the reply is the
  one of the last command.
- **Empty parts are left out,** so a `;` at the end does no harm.
- **`space` and `move-to-space` come last.** macOS finishes the switch after the command has
  returned, so a command after it would act on the desktop you are leaving. Anywhere else
  they are an error: `'space' must come last in a chain`. A `move-to-space` with `--stay`
  switches nothing, so it may go anywhere in the chain.
- **Reports, `quit` and `subscribe` cannot be part of a chain,** and neither can `--json`.
  The error names the command: `'status' cannot be part of a chain`.

In a terminal, put the chain in quotes. Without them the shell reads `;` as the end of the
`iguana` command.

### Before the permission is granted

Until Iguana has the Accessibility permission, only `status`, `reload`, `settings`, `tour`,
`update`, `mode` and `quit` work. Every other command replies:

```text
error: Iguana needs Accessibility permission (System Settings > Privacy & Security > Accessibility)
```

## Windows

Most of these act on the focused window and need it to be tiled. When it is not, they reply
`error: the focused window is not tiled`.

### Acting on another window

From the command line, `--window ID` makes a command act on the window with that id instead
of the focused one, exactly as if it had the focus. The focus stays where it is. The exception
is `zoom --window ID`: a zoomed window is raised, and raising a window of the app in front
gives it the focus.
[`list-windows`](#list-windows) gives the ids. A shortcut cannot name a window.

These commands take it: `focus`, `move`, `join`, `resize`, `flip`, `stack`, `balance`,
`split`, `arrange`, `float`, `zoom`, `close`, `move-to-space`, `move-to-display` and
`place`. With any other command the line is not sent:

```text
iguana: 'space' does not take --window
```

- `focus --window ID` focuses that window. It takes no direction.
- `move`, `join`, `resize`, `flip`, `stack`, `balance` and `zoom` need the window to be tiled
  on a desktop that is being shown. `balance` evens out that window's desktop.
- `split` and `arrange` act on the layout that window is tiled in.
- `float`, `close` and `place` work for any window Iguana knows about, on any desktop. `place`
  floats a tiled window first, as it does the focused one.
- `move-to-space` sends that window from whichever desktop it is on. With `--follow`, the
  default, you go with it and it gets the focus. With `--stay`, the focus only moves if that
  window had it.
- `move-to-display` takes that window to another display. The focus stays with it only if it
  had the focus.

| Reply | When |
| --- | --- |
| `error: no window ID` | Iguana knows no window with that id. It has closed, or it is not a window Iguana tracks. |
| `error: window ID is not tiled on a desktop being shown` | The command needs a tile, and the window floats or is on a desktop that is not being shown. |
| `error: not while the welcome tour is on screen` | The [welcome tour](#tour) has the keyboard. |

[Command line](/reference/command-line/#acting-on-another-window) has examples for scripts.

### `focus`

```text
focus left|right|up|down|recent
focus --window ID
```

Focuses the nearest window in that direction. With `--window ID`, it focuses the window with
that id instead, as a click on it would. See [Acting on another window](#acting-on-another-window).

"Nearest" is judged by where windows are on screen, not by the layout tree. Floating windows
count. Windows that line up with the focused one are preferred over windows that are only
diagonally in that direction. Across displays, focus moves to the nearest window on the next
display.

A [stack](/guides/how-tiling-works/#stack) is the exception, because its windows overlap. In
the direction the stack runs, `focus` goes to the next or the previous window of the stack,
and from the last one on to the neighbour beyond it. A stack that is entered from the side
gives the window it has in front.

If no window is focused, the frontmost window on the desktop is focused instead.

`focus recent` goes back to the window that had the focus before the focused one. Press it
again to return. Tiled and floating windows count; dialogs and sheets do not. It skips
windows that are not on screen: those on a desktop that is not showing, minimised windows
and the windows of a hidden app. It never switches desktop, but it does reach a window on
another display.

| Reply | When |
| --- | --- |
| `ok` | A window was focused. |
| `ok: nothing in that direction` | There is no window that way. |
| `ok: no windows here` | There are no windows on screen. |
| `ok: no other recent window` | `recent` found no window it can go back to. |

With [`mouse-follows-focus`](/reference/configuration/#mouse-follows-focus) on, the pointer
moves to the centre of the newly focused window.

The opposite setting, [`focus-follows-mouse`](/reference/configuration/#focus-follows-mouse),
focuses the window the pointer comes to rest on. It never undoes this command: after `focus`
moved the focus, the pointer has to be moved before it counts again.

### `move`

```text
move left|right|up|down
```

Moves the focused window one step in the layout: it trades places with a neighbouring
window, enters a neighbouring group, or leaves its own group on that side. At the edge of the
layout it carries on to the display in that direction, if there is one.
[How tiling works](/guides/how-tiling-works/#move) has diagrams of each case.

| Reply | When |
| --- | --- |
| `ok` | The window moved. |
| `ok: already at the edge` | Nothing further that way, and no display there. |
| `error: the focused window is not tiled` | |

### `join`

```text
join left|right|up|down
```

Puts the focused window and its neighbour in that direction into one slot, split the other
way. Joining left or right puts one above the other. Joining up or down puts them side by side. If the
neighbour is already a group, the window is added to the end of the group.
[Diagram](/guides/how-tiling-works/#join).

| Reply | When |
| --- | --- |
| `ok` | The windows were joined. |
| `ok: no neighbour in that direction` | |
| `error: the focused window is not tiled` | |

### `resize`

```text
resize grow|shrink [width|height]
```

Changes the focused window's share of its container by one step. The step is
[`resize-step`](/reference/configuration/#resize-step), 5% by default.

- Without `width` or `height`, the nearest container in which the window has a visible
  neighbour is used.
- `width` uses the nearest side-by-side container, `height` the nearest top-to-bottom one.
- The windows of a [stack](#stack) all have the same size. From inside a stack, the stack as
  a whole grows or shrinks.

The words can come in either order: `resize width grow` is the same as `resize grow width`.

| Reply | When |
| --- | --- |
| `ok` | The share changed. |
| `ok: nothing to resize against` | There is no neighbour in that direction, for example with one window on the desktop. |
| `error: the focused window is not tiled` | |

### `flip`

```text
flip
```

Switches the container that holds the focused window between side-by-side and top-to-bottom.
[Diagram](/guides/how-tiling-works/#flip).

| Reply | When |
| --- | --- |
| `ok` | The container was flipped. |
| `error: cannot flip` | |
| `error: the focused window is not tiled` | |

### `stack`

```text
stack
```

Switches the container that holds the focused window between tiles and a stack. In a stack
the windows overlap: each takes nearly the whole container and is shifted by
[`stack-peek`](/reference/configuration/#stack-peek) from the one before it, so a strip of
every window stays in view. No window is hidden. [How tiling works](/guides/how-tiling-works/#stack)
says what the other commands do in a stack.

| Reply | When |
| --- | --- |
| `ok: stacked` | The windows of the container now overlap. |
| `ok: unstacked` | They are tiles again. |
| `ok: no other window to stack with` | The focused window is the only one in the layout. |
| `error: the focused window is not tiled` | |

### `balance`

```text
balance
```

Gives every window on the focused window's desktop an equal share again. With
[`--window`](#acting-on-another-window), on that window's desktop.

| Reply | When |
| --- | --- |
| `ok` | |
| `error: the focused window is not tiled` | |

### `split`

```text
split horizontal|vertical|auto
```

Chooses where the next window that opens beside the focused window goes. `horizontal` puts it
side by side with the focused window, `vertical` puts it below. `auto` goes back to what
[`auto-split`](/reference/configuration/#auto-split) says.

The choice belongs to the focused window and is used once, by the next window that opens next
to it. It works whatever `auto-split` is set to. It is forgotten when the window closes,
floats or leaves its desktop. With [`--window`](#acting-on-another-window), the choice belongs
to that window.

A new window next to a window in a [stack](#stack) joins the stack, whatever `split` says.
[Where a new window opens](/guides/how-tiling-works/#where-a-new-window-opens) has a diagram.

| Reply | When |
| --- | --- |
| `ok: the next window opens beside it` | `horizontal`. |
| `ok: the next window opens below it` | `vertical`. |
| `ok: automatic` | `auto`. |
| `ok: new windows join the stack this window is in` | The focused window is in a stack. Nothing is remembered. |
| `error: the focused window is not tiled` | |

### `arrange`

```text
arrange columns|rows|grid|main
```

Rearranges every window on the focused window's desktop at once:

- `columns`: every window side by side, with equal widths.
- `rows`: every window top to bottom, with equal heights.
- `grid`: rows of equal tiles, filled in order. Each row has as many windows as the square
  root of their number, rounded up. The last row can have fewer, wider windows.
- `main`: the focused window on the left, with 60% of the width. The others are top to bottom
  on the right and share the rest equally.

The windows go in reading order of where they are now: top to bottom, then left to right. With
`main`, the focused window is taken out first and the others keep that order. Stacks on the
desktop become tiles, a [zoomed](#zoom) window goes back to its tile, and the focused window
stays focused. Windows that are not showing, such as minimised ones, go at the end and take no
room until they come back.

This happens once. The result is an ordinary layout, and every other command changes it as
usual. [Arrange a desktop at once](/guides/how-tiling-works/#arrange-a-desktop-at-once) has
diagrams. With [`--window`](#acting-on-another-window), that window's desktop is rearranged.

| Reply | When |
| --- | --- |
| `ok` | The desktop was rearranged. |
| `ok: nothing to arrange` | Fewer than two windows are on screen. `main` with one window replies `ok`. |
| `error: the focused window is not tiled` | |

### `float`

```text
float
```

Toggles tiling for the focused window. A floating window leaves the layout and stays where it
is. Tiling it again adds it to the layout like a newly opened window. See
[Floating windows and rules](/guides/floating-windows/).

| Reply | When |
| --- | --- |
| `ok: floating` | The window now floats. |
| `ok: tiled` | The window is tiled again. |
| `error: no focused window` | |
| `error: this window cannot be tiled` | It is a dialog, a sheet or a fixed-size window. |

### `place`

```text
place center|left|right|top|bottom|top-left|top-right|bottom-left|bottom-right|full
```

Puts the focused window in a part of its display, and leaves it floating there. With
[`--window`](#acting-on-another-window), that window is placed. The part is
cut from the area tiled windows use: the display without the menu bar and the Dock, inside
the [outer gaps](/reference/configuration/#outer).

| Position | Where the window goes |
| --- | --- |
| `center` | The middle of the area, at the window's own size. A window bigger than the area is shrunk to fit. |
| `left`, `right` | The left or the right half. |
| `top`, `bottom` | The top or the bottom half. |
| `top-left`, `top-right`, `bottom-left`, `bottom-right` | A quarter. |
| `full` | The whole area. Unlike [`zoom`](#zoom), the window stays floating. |

Halves and quarters leave the [inner gap](/reference/configuration/#inner) between them, as
tiled windows do.

A tiled window is floated first, exactly as [`float`](#float) floats it. The window glides to
its place, following the [`[animation]`](/reference/configuration/#animation) settings.

Some apps will not let a window get smaller than a minimum size, or change its size at all.
Such a window still goes against the same edges: with `left` its left edge is on the left of
the area, with `bottom-right` its bottom-right corner is in that corner.

`place` also works while tiling is [paused](#pause). It moves only the window you asked it to.

There are no default shortcuts for `place`.
[Floating windows](/guides/floating-windows/#place-a-floating-window-from-the-keyboard) suggests
some.

| Reply | When |
| --- | --- |
| `ok` | The window was placed. |
| `ok: floating` | The window was tiled. It now floats, and was placed. |
| `error: no focused window` | |
| `error: this window cannot be moved` | |
| `error: a fullscreen window cannot be placed` | |
| `error: cannot read the window's position` | |
| `error: no display` | |

### `zoom`

| Reply | When |
| --- | --- |
| `ok` | |
| `error: the focused window is not tiled` | |

| Reply | When |
| --- | --- |
| `ok` | |

### `undo`

```text
undo
```

Takes back the last change to the layout of the desktop you are on. That is the desktop of
the focused window if it is tiled, and otherwise the desktop on the display the pointer is
on. Run it again to go further back.

A change is one of these:

- `move`, `join`, `resize`, `flip`, `stack`, `balance` and `arrange`,
- `move` and `move-to-display` taking a tiled window to another display,
- dragging a tile onto another to swap them, take half of one or join a stack,
- dragging the edge of a tile to resize it.

Windows opening and closing are not changes, and neither are `zoom`, `float`, `split` and
`place`.

The layout comes back without the windows that have closed, floated or left the desktop
since, and a window that has opened since is placed like a new window. `undo` never moves a
window to another display or desktop. A `move` or a drag that takes a window to another
display changes the layouts on both, and each keeps that change as its own.

Each desktop on each display keeps its own last 50 changes. They last until Iguana quits:
unlike the layouts, they are not kept across a restart.

| Reply | When |
| --- | --- |
| `ok: undone` | The layout is back as it was before the change. |
| `ok: nothing to undo` | There is no change left to take back on this desktop. |

### `redo`

```text
redo
```

Makes the last change that `undo` took back on this desktop again. A new change clears what
there is to redo.

| Reply | When |
| --- | --- |
| `ok: redone` | |
| `ok: nothing to redo` | Nothing has been undone since the last change. |

## Apps

### `focus-app`

```text
focus-app NAME|BUNDLE-ID
```

Brings an app forward, or opens it. Iguana never hides a window, so there is no scratchpad to
keep one in. Instead, give each app you call up often a shortcut of its own. See
[Customising shortcuts](/guides/shortcuts/#bring-an-app-forward-or-open-it).

`NAME` is part of an app's name and `BUNDLE-ID` is its bundle identifier, matched exactly, as
in a rule's [`app`](/reference/configuration/#app). Case is ignored. A name can be several
words: `focus-app visual studio code`.

When more than one running app matches, the best match wins: the bundle id, then the whole
name, then a name that starts with the text, then a name that contains it. So `focus-app code`
is Visual Studio Code, which calls itself Code, and not Xcode. Of two apps that match equally
well, the one you used last wins.

- **The app is running.** Its window that had the focus last gets the focus again, if that
  window is on a desktop being shown, on any display. Otherwise its frontmost window on screen
  does.
- **The app has the focus already.** Its next window on screen gets the focus, so pressing the
  key again goes through the app's windows one by one. With one window, nothing changes.
- **All of its windows are minimised.** The one that had the focus most recently comes back
  out of the Dock and gets the focus.
- **None of its windows is on screen.** They are on another desktop, or the app is hidden.
  The app is brought forward and macOS shows one of its windows, which can take you
  to another desktop.
- **The app is not running.** It is opened. A bundle id is looked up by macOS. A name has to be
  the whole name of the app, as its file is called without `.app`, in `/Applications`,
  `/Applications/Utilities`, `/System/Applications`, `/System/Applications/Utilities` or
  `~/Applications`.

With [`mouse-follows-focus`](/reference/configuration/#mouse-follows-focus) on, the pointer
moves to the centre of the window that gets the focus.

| Reply | When |
| --- | --- |
| `ok` | A window of the app has the focus. |
| `ok: activated NAME` | None of its windows was on screen, so the app was brought forward. |
| `ok: brought back a minimised window` | All of its windows were minimised; the most recently used one is back. |
| `ok: opening NAME` | The app was not running, and is being opened. |
| `error: no app called 'NAME'` | No running app matches, and no app of that name was found. |

### `switcher`

```text
switcher
```

Opens the window switcher in the middle of the display you are using: a search field above a
list of your windows. Type part of a window's title or of its app's name, then press
<kbd>return</kbd> to focus the window. The focus moves the way a click on a window in the
menu bar item's drawing moves it.
[Find a window](/guides/shortcuts/#find-a-window) shows it in use.

The list holds every standard window Iguana knows about, tiled or floating. The window you
used last comes first and the focused window comes last, so opening the switcher and pressing
<kbd>return</kbd> takes you back to the window you were on before.

Windows that are not on screen are listed too. A row says when its window is minimised, when
its app is hidden, or when it is in another Stage Manager stage. When your windows are on
more than one desktop, each row also gives its desktop's number. Picking a minimised window
brings it out of the Dock, picking a window of a hidden app shows the app again, and picking
a window on another desktop takes you there.

| Key | What it does |
| --- | --- |
| Letters and digits | Narrow the list. |
| <kbd>up</kbd> and <kbd>down</kbd>, or <kbd>ctrl</kbd>+<kbd>p</kbd> and <kbd>ctrl</kbd>+<kbd>n</kbd> | Move the selection. It goes round from the last row to the first. |
| <kbd>return</kbd> | Focus the selected window. |
| <kbd>esc</kbd> | Close the switcher. The focus stays where it was. |

A click on a row focuses that window, and a click outside the switcher closes it.

What you type matches the letters of the app's name and the title in order, ignoring case,
accents and spaces: `gc` finds Google Chrome. Windows whose app's name starts with what you
typed come first, then windows where it starts words, then the rest. Windows that match
equally well stay in the order you last used them.

While the switcher is open, Iguana's other shortcuts keep working, and running `switcher`
again moves the selection down one row.

| Reply | When |
| --- | --- |
| `ok` | The switcher opened, or its selection moved down one row. |
| `ok: no windows to switch to` | Iguana knows no window to list. |

## Desktops

"Space" is Apple's name for a desktop, and it is the word these two commands use.

### `space`

```text
space N|next|prev|recent
```

Switches to a desktop by pressing Mission Control's own shortcut. `N` is a number from 1 to
16, counted across all displays the way Mission Control numbers desktops. `previous` is
accepted for `prev`.

`recent` is the desktop the current display showed before the one it shows now, however you
left it: a shortcut, a swipe or Mission Control. Run it twice to go back and forth between
two desktops. Iguana remembers the desktop itself, not its number, so adding or removing
desktops does not change where `recent` goes. Fullscreen Spaces are not desktops and are
skipped. The current display is the one holding the focused tiled window, or the one under
the pointer.

| Reply | When |
| --- | --- |
| `ok` | The system shortcut was pressed. |
| `ok: already on desktop N` | |
| `ok: no previous desktop` | This display has shown no other desktop since Iguana started, or that desktop was removed. |
| `error: there are only N desktops` | The number is higher than the number of desktops. |
| `error: could not trigger the system shortcut` | |
| `error: no display` | |

### `move-to-space`

```text
move-to-space N|next|prev|recent
move-to-space N|next|prev|recent --stay
```

Takes the focused window to a desktop and goes with it. With `--stay`, the window is sent
and you stay where you are. `--follow` spells out the default. `--stay` and `--follow`
cannot be combined.

`N` is a number from 1 to 16, counted across all displays. `next` and `prev` mean the next
and previous desktop on the current display. `recent` is the desktop that display showed
before, as for [`space recent`](#space). `previous` is accepted for `prev`. The window does
not have to be tiled.

With [`--window ID`](#acting-on-another-window), the window with that id is sent instead, from
whichever desktop it is on. `next` and `prev` then count from that window's desktop.

The window joins the layout of its new desktop like a newly opened window. On systems where
the quick route is not available the window is carried across by its title bar, which always
follows the window. See
[Desktops and displays](/guides/desktops-and-displays/#send-a-window-to-another-desktop).

| Reply | When |
| --- | --- |
| `ok` | The window was moved, or the slower route was started. |
| `ok: already on desktop N` | |
| `ok: no desktop in that direction` | `next` or `prev` at the end of the display's desktops. |
| `ok: no previous desktop` | `recent`, and the display has shown no other desktop, or that desktop was removed. |
| `error: no focused window` | |
| `error: there are only N desktops` | |
| `error: a fullscreen window cannot be sent to another desktop` | |
| `error: a move is already in progress` | The slower route is still carrying a window. |
| `error: cannot tell which desktop is showing` | |
| `error: cannot read the window's position` | |
| `error: the system did not move the window` | The quick route is not available, and the window named with `--window` is not on screen to be carried. |
| `error: no display` | |

## Displays

These two commands go to the next or the previous display, or to a display by its number.
Displays are numbered from 1, left to right by their left edge, and top to bottom where two
displays share a left edge. [`list-spaces`](#list-spaces) shows the number of each display.

### `focus-display`

```text
focus-display next|prev|N
```

Focuses a window on another display. `N` is a display number from 1 to 16. `next` and `prev`
go to the next and previous display in that order, counted from the display that holds the
focused window, and wrap around at the ends. `previous` is accepted for `prev`.

The window that gets the focus is the first of these:

1. The window that last had the focus in the layout of that display, if it is on screen.
2. The tiled window nearest the centre of the display.
3. The frontmost window on the display that is not tiled, such as a floating one.

With [`mouse-follows-focus`](/reference/configuration/#mouse-follows-focus) on, the pointer
moves to the centre of the newly focused window. When the display has no window, the pointer
moves to the centre of the display instead, so a click lands there.

| Reply | When |
| --- | --- |
| `ok` | A window was focused. |
| `ok: no window on that display` | |
| `ok: only one display` | `next` or `prev` with only one display connected. A number works even then: `focus-display 1` is that display. |
| `error: there is no display N (there are M)` | The number is higher than the number of displays. |

### `move-to-display`

```text
move-to-display next|prev|N
```

Takes the focused window to another display. The focus stays with the window. With
[`--window`](#acting-on-another-window), that window is taken and the focus stays where it
is. `N`, `next` and `prev` mean the same as for [`focus-display`](#focus-display), counted
from the display the window is on. The window does not have to be tiled.

A tiled window joins the layout of the desktop that display is showing, beside the window
last focused there, as when [`move`](#move) carries a window across at the edge of the
layout. A floating window stays floating. It keeps its size, made smaller if the display has
not got the room, and its place in proportion: a window against the right edge lands against
the right edge, a window in the middle lands in the middle.

| Reply | When |
| --- | --- |
| `ok` | The window was moved. |
| `ok: already on display N` | The window is on that display, so with one display `move-to-display 1` answers this. |
| `ok: only one display` | `next` or `prev` with only one display connected. A number works even then. |
| `error: no focused window` | |
| `error: there is no display N (there are M)` | The number is higher than the number of displays. |
| `error: display N is showing a fullscreen app` | Iguana leaves fullscreen Spaces alone. |
| `error: a fullscreen window cannot be sent to another display` | |
| `error: cannot read the window's position` | |

### `apply-rules`

```text

```

Does what your [rules](/reference/configuration/#rule) say with the windows that are already
open. Otherwise a rule only sends a window where it belongs as the window opens. You stay on
the desktop you are on.

- **Floating** is decided again for every window, as when the config is reloaded. A window you
  floated or tiled by hand with [`float`](#float) keeps your choice.
- **A rule with a `desktop`** sends each standard window it matches to that desktop, the same
  way as a new window. This needs the system's window-management bridge: see

A window that cannot be moved stays where it is, and the log says why.

shortcut.

| --- | --- |
| `ok: N window(s) moved` | N windows went to the desktop or the display their rule names. |
| `ok: nothing to move` | Every window is where its rule says, or no rule names a desktop or a display. |
| `error: tiling is paused` | While tiling is paused no window is moved. |

### `update`

```text
update
```

Asks GitHub now whether a newer Iguana has been released, whatever
[`updates.check`](/reference/configuration/#check) says, and answers with one line once GitHub
has answered. That usually takes a moment, and never more than about ten seconds.

| Reply | When |
| --- | --- |
| `ok: Iguana 0.2.1 is the latest version` | Nothing newer has been released. The number is the version you are running. |
| `ok: Iguana 0.2.2 is available at https://github.com/Chandram-Dutta/iguana/releases/tag/v0.2.2` | The newer version, and the address of its page. |
| `error: could not check for a newer version: …` | The check could not be made, and why: the Mac is offline, or GitHub did not answer as expected. |

or your Mac: see [The one network request](/help/under-the-hood/#the-one-network-request).

hand also counts as the day's check, so the next one Iguana makes by itself is a day later.

A shortcut has nowhere to print an answer. Bound to one, `update` starts the check and
replies `ok: checking`; a newer version then shows in the menu of the menu bar item, as it
does after the daily check, provided `updates.check` is on.

## Reports

These print information and change nothing. The window titles, app names, numbers and
display names in the examples are made up.

### JSON output

From a terminal, each of the four reports takes `--json` and answers with one JSON document
instead of text, for status bars and scripts. Without the flag the output is the text shown
below, as it always was.

```sh
iguana list-spaces --json | jq '.desktops[] | select(.active) | .number'
```

- **Keys are lower camel case,** such as `bundleId` and `desktopCount`. Values that are words
  are too, such as `notOnScreen`.
- **Something that is not known is `null`.** Its key is still there, so every document of a
  kind has the same shape. The one exception is the layout in [`tree`](#tree), where a
  container and a window have different keys.
- **The output is stable.** It is pretty-printed with the keys sorted, so the same facts give
  the same text. Keys may be added in later versions. A key is not renamed or removed.
- **An error is not JSON.** When the report cannot be made, the reply is the usual
  `error: …` line and the exit status is 1, so check the status before parsing.
- **Titles stay on this Mac.** A document goes to whoever ran the command and nowhere else.
- **`--json` is for the command line.** A shortcut has nowhere to print a document, so
  `--json` in [`[bindings]`](/reference/configuration/#bindings) is a warning. No other
  command takes it.

[Status bars and scripts](/guides/status-bars-and-scripts/) puts these to use.

### `list-windows`

```text

list-windows --json
```

Lists every window Iguana knows about, one per line: a `*` for the focused window, the
window's number, its state, its app and its title, separated by tabs.

```text

  1320	not on screen	Notes	Notes
  1402	floating	Calculator	Calculator
```

The states are `tiled`, `floating`, `unmanaged` and `not on screen`. They are explained under
[What gets tiled](/guides/floating-windows/#what-gets-tiled).

With `--json`:

```json
        "height" : 933,

        "x" : 8,
        "y" : 41
      },
      "id" : 1187,
      "state" : "tiled",
      "title" : "zsh"
    },
```


### `subscribe`

```text
subscribe [event ...]
```

Stays connected and prints one line of JSON for each event, as it happens, until Iguana quits.
The events are the ones [`[hooks]`](/reference/configuration/#hooks) knows, such as
`desktop-changed` and `focus-changed`. Name one or more to hear only those. With none, you hear
every event.

```sh
iguana subscribe desktop-changed focus-changed
```

```jsonl
{"desktop":2,"display":"Built-in Retina Display","event":"desktop-changed"}
{"app":"Safari","desktop":2,"display":"Built-in Retina Display","event":"focus-changed","title":"Apple","window-id":1203}
{"app":"Terminal","desktop":2,"display":"Built-in Retina Display","event":"focus-changed","title":"zsh","window-id":1187}
```

- **The current state comes first.** As soon as you subscribe, Iguana sends one
  `desktop-changed` line for each display, one `layout-changed` line for each display showing
  a desktop, one `pause-changed` line and one `focus-changed` line, as if they had just
  happened, so a status bar can draw at once. Only the events you asked for are sent, and
  `window-created` and `window-closed` have no state, so they get no initial line.
- **Each line says what a hook would be told.** There is one key for each of the
  [variables of a hook](/reference/configuration/#what-the-command-is-given): its name in lower
  case, without `IGUANA_`, and with `-` for `_`. `IGUANA_WINDOW_ID` is `window-id`.
- **Only three keys are typed.** `desktop` and `window-id` are numbers, `paused` is a boolean,
  and an empty value is `null` for every key. Everything else is always a string, even when it
  looks like a number or `true`: a window titled `42` comes through as `"42"`. So `desktop` is
  `null` on a fullscreen Space, and `window-id` is `null` when no window has the focus.
- **One event, one line.** The keys are sorted, and a line break in a window title is written
  as `\n`, so every line is a whole JSON object.
- **The same rules as hooks.** An event is sent only when something really changed, whether or
  not a hook is set for it. Nothing is sent before tiling starts; when it does, the current
  state comes first. See [How a command is run](/reference/configuration/#how-a-command-is-run).
- **It ends when Iguana quits,** and the command exits with status 0. Press Control-C to stop
  it yourself.
- **Read as you go.** A subscriber that stops reading is let go once 256 lines are waiting
  for it, so it never slows Iguana down.

`subscribe` is for the command line, and its output is always JSON, so it takes no `--json`.
A name that is not an event is a mistake, and the tool stops with exit code 2. An Iguana too
old for `subscribe` answers with one error line that is not JSON, and the tool exits 1.

| Reply | When |
| --- | --- |
| `error: subscribe only works from the command line` | From a shortcut, which has nowhere to print. |
