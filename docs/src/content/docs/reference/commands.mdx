This page lists every command Iguana understands, with its arguments and its replies.

## Running a command

A command can be run in two ways:

- **From a shortcut.** The right-hand side of an entry in
  [`[bindings]`](/reference/configuration/#bindings) is a command.
- **From a terminal.** Put `iguana` in front of it: `iguana focus left`. See
  [Command line](/reference/command-line/).

Commands are written in lower case, with single words separated by spaces. Upper case is
accepted and treated as lower case.

### Replies

Every command answers with one line, or with a report.

- `ok` means the command did what it says.
- `ok: …` means there was nothing to do, and says why. For example `ok: nothing in that direction`.
- `error: …` means the command could not run, and says why.

In a terminal the reply is printed. For a shortcut, the last reply is shown by
[`status`](#status), and replies that start with `error` are written to the log.

### Before the permission is granted

Until Iguana has the Accessibility permission, only `status`, `reload`, `settings`, `tour` and
`quit` work. Every other command replies:

```text
error: Iguana needs Accessibility permission (System Settings > Privacy & Security > Accessibility)
```

## Windows

Most of these act on the focused window and need it to be tiled. When it is not, they reply
`error: the focused window is not tiled`.

### `focus`

```text
focus left|right|up|down
```

Focuses the nearest window in that direction.

"Nearest" is judged by where windows are on screen, not by the layout tree. Floating windows
count. Windows that line up with the focused one are preferred over windows that are only
diagonally in that direction. Across displays, focus moves to the nearest window on the next
display.

If no window is focused, the frontmost window on the desktop is focused instead.

| Reply | When |
| --- | --- |
| `ok` | A window was focused. |
| `ok: nothing in that direction` | There is no window that way. |
| `ok: no windows here` | There are no windows on screen. |

With [`mouse-follows-focus`](/reference/configuration/#mouse-follows-focus) on, the pointer
moves to the centre of the newly focused window.

### `move`

```text
move left|right|up|down
```

Moves the focused window one step in the layout: it trades places with a neighbouring
window, enters a neighbouring group, or leaves its own group on that side. At the edge of the
layout it carries on to the display in that direction, if there is one.
[How tiling works](/guides/how-tiling-works/#move) has diagrams of each case.

| Reply | When |
| --- | --- |
| `ok` | The window moved. |
| `ok: already at the edge` | Nothing further that way, and no display there. |
| `error: the focused window is not tiled` | |

### `join`

```text
join left|right|up|down
```

Puts the focused window and its neighbour in that direction into one slot, split the other
way. Joining left or right stacks them. Joining up or down puts them side by side. If the
neighbour is already a group, the window is added to the end of the group.
[Diagram](/guides/how-tiling-works/#join).

| Reply | When |
| --- | --- |
| `ok` | The windows were joined. |
| `ok: no neighbour in that direction` | |
| `error: the focused window is not tiled` | |

### `resize`

```text
resize grow|shrink [width|height]
```

Changes the focused window's share of its container by one step. The step is
[`resize-step`](/reference/configuration/#resize-step), 5% by default.

- Without `width` or `height`, the nearest container in which the window has a visible
  neighbour is used.
- `width` uses the nearest side-by-side container, `height` the nearest stacked one.

The words can come in either order: `resize width grow` is the same as `resize grow width`.

| Reply | When |
| --- | --- |
| `ok` | The share changed. |
| `ok: nothing to resize against` | There is no neighbour in that direction, for example with one window on the desktop. |
| `error: the focused window is not tiled` | |

### `flip`

```text
flip
```

Switches the container that holds the focused window between side-by-side and stacked.
[Diagram](/guides/how-tiling-works/#flip).

| Reply | When |
| --- | --- |
| `ok` | The container was flipped. |
| `error: cannot flip` | |
| `error: the focused window is not tiled` | |

### `balance`

```text
balance
```

Gives every window on the focused window's desktop an equal share again.

| Reply | When |
| --- | --- |
| `ok` | |
| `error: the focused window is not tiled` | |

### `float`

```text
float
```

Toggles tiling for the focused window. A floating window leaves the layout and stays where it
is. Tiling it again adds it to the layout like a newly opened window. See
[Floating windows and rules](/guides/floating-windows/).

| Reply | When |
| --- | --- |
| `ok: floating` | The window now floats. |
| `ok: tiled` | The window is tiled again. |
| `error: no focused window` | |
| `error: this window cannot be tiled` | It is a dialog, a sheet or a fixed-size window. |

### `zoom`

```text
zoom
```

Toggles the focused window filling the desktop, inside the outer gaps. The layout underneath
is unchanged. One window per desktop can be zoomed.

| Reply | When |
| --- | --- |
| `ok` | |
| `error: the focused window is not tiled` | |

### `close`

```text
close
```

Closes the focused window by pressing its close button, as a click would. It works for
floating windows too.

| Reply | When |
| --- | --- |
| `ok` | |
| `error: no focused window` | |
| `error: this window has no close button` | |

## Desktops

"Space" is Apple's name for a desktop, and it is the word these two commands use.

### `space`

```text
space N|next|prev
```

Switches to a desktop by pressing Mission Control's own shortcut. `N` is a number from 1 to
16, counted across all displays the way Mission Control numbers desktops. `previous` is
accepted for `prev`.

| Reply | When |
| --- | --- |
| `ok` | The system shortcut was pressed. |
| `ok: already on desktop N` | |
| `error: there are only N desktops` | The number is higher than the number of desktops. |
| `error: could not trigger the system shortcut` | |
| `error: no display` | |

### `move-to-space`

```text
move-to-space N|next|prev
move-to-space N|next|prev --stay
```

Takes the focused window to a desktop and goes with it. With `--stay`, the window is sent
and you stay where you are. `--follow` spells out the default. `--stay` and `--follow`
cannot be combined.

`N` is a number from 1 to 16, counted across all displays. `next` and `prev` mean the next
and previous desktop on the current display. `previous` is accepted for `prev`. The window
does not have to be tiled.

The window joins the layout of its new desktop like a newly opened window. On systems where
the quick route is not available the window is carried across by its title bar, which always
follows the window. See
[Desktops and displays](/guides/desktops-and-displays/#send-a-window-to-another-desktop).

| Reply | When |
| --- | --- |
| `ok` | The window was moved, or the slower route was started. |
| `ok: already on desktop N` | |
| `ok: no desktop in that direction` | `next` or `prev` at the end of the display's desktops. |
| `error: no focused window` | |
| `error: there are only N desktops` | |
| `error: a fullscreen window cannot be sent to another desktop` | |
| `error: a move is already in progress` | The slower route is still carrying a window. |
| `error: cannot tell which desktop is showing` | |
| `error: cannot read the window's position` | |
| `error: no display` | |

## Iguana itself

### `pause`

```text
pause
```

Toggles tiling. While paused, Iguana does not move or resize any window, and the menu bar
icon is a pause mark instead of a drawing of the desktop.

| Reply | When |
| --- | --- |
| `ok: paused` | |
| `ok: tiling` | |

### `reload`

```text
reload
```

Reads the config file again. The file is also reloaded by itself when it is saved.

| Reply | When |
| --- | --- |
| `ok: loaded PATH` | The file loaded cleanly. |
| `ok: loaded PATH with warnings:` | Followed by one line for each warning. |
| `error: PATH: …` | The file has a syntax error. The message includes the line. The previous settings are kept. |
| `ok: no config file at PATH, using the built-in defaults` | |

### `settings`

```text
settings
```

Opens the [settings window](/guides/settings-window/), the same as choosing **Settings…**
from the menu bar item.

| Reply | When |
| --- | --- |
| `ok` | |

### `tour`

```text
tour
```

Shows the [welcome tour](/start/install/#the-welcome-tour) again, the same as choosing
**Welcome Tour…** from the menu bar item.

While the tour is in front, commands go to its practice desktop instead of your real
windows and reply `ok: in the welcome tour`. The tour acts on `focus`, `move`, `resize`,
`space` and `move-to-space` once it has reached the lesson for them, and ignores every other
command, `settings` and `pause` included. `status`, `reload`, `list-windows`, `list-spaces`,
`tree` and `quit` work as usual.

| Reply | When |
| --- | --- |
| `ok` | |

### `quit`

```text
quit
```

Quits Iguana. Layouts are saved first. No window moves.

| Reply | When |
| --- | --- |
| `ok` | |

## Reports

These print information and change nothing. The window titles, app names, numbers and
display names in the examples are made up.

### JSON output

From a terminal, each of the four reports takes `--json` and answers with one JSON document
instead of text, for status bars and scripts. Without the flag the output is the text shown
below, as it always was.

```sh
iguana list-spaces --json | jq '.desktops[] | select(.active) | .number'
```

- **Keys are lower camel case,** such as `bundleId` and `desktopCount`. Values that are words
  are too, such as `notOnScreen`.
- **Something that is not known is `null`.** Its key is still there, so every document of a
  kind has the same shape. The one exception is the layout in [`tree`](#tree), where a
  container and a window have different keys.
- **The output is stable.** It is pretty-printed with the keys sorted, so the same facts give
  the same text. Keys may be added in later versions. A key is not renamed or removed.
- **An error is not JSON.** When the report cannot be made, the reply is the usual
  `error: …` line and the exit status is 1, so check the status before parsing.
- **Titles stay on this Mac.** A document goes to whoever ran the command and nowhere else.
- **`--json` is for the command line.** A shortcut has nowhere to print a document, so
  `--json` in [`[bindings]`](/reference/configuration/#bindings) is a warning. No other
  command takes it.

[Status bars and scripts](/guides/status-bars-and-scripts/) puts these to use.

### `list-windows`

```text
list-windows
list-windows --json
```

Lists every window Iguana knows about, one per line: a `*` for the focused window, the
window's number, its state, its app and its title, separated by tabs.

```text
* 1187	tiled	Terminal	zsh
  1203	tiled	Safari	Start Page
  1320	not on screen	Notes	Notes
  1402	floating	Calculator	Calculator
```

The states are `tiled`, `floating`, `unmanaged` and `not on screen`. They are explained under
[What gets tiled](/guides/floating-windows/#what-gets-tiled).

With `--json`:

```json
{
  "windows" : [
    {
      "app" : "Terminal",
      "bundleId" : "com.apple.Terminal",
      "desktop" : 1,
      "display" : "Built-in Retina Display",
      "focused" : true,
      "frame" : {
        "height" : 933,
        "width" : 748,
        "x" : 8,
        "y" : 41
      },
      "id" : 1187,
      "state" : "tiled",
      "title" : "zsh"
    },
    {
      "app" : "Notes",
      "bundleId" : "com.apple.Notes",
      "desktop" : 2,
      "display" : "Built-in Retina Display",
      "focused" : false,
      "frame" : null,
      "id" : 1320,
      "state" : "notOnScreen",
      "title" : "Notes"
    }
  ]
}
```

| Key | Value |
| --- | --- |
| `id` | The window's number. It stays the same until the window closes. |
| `app` | The name of the window's app. |
| `bundleId` | The app's bundle identifier, or `null`. |
| `title` | The window's title. |
| `state` | `tiled`, `floating`, `unmanaged` or `notOnScreen`. |
| `focused` | `true` for the focused window. |
| `desktop` | The number of the desktop the window is on, or `null` when Iguana cannot tell, as for a window in native fullscreen. |
| `display` | The name of the display the window is on, or `null`. |
| `frame` | Where the window is, in points from the top-left corner of the main display. `null` when the window is not on screen. |

### `list-spaces`

```text
list-spaces
list-spaces --json
```

Shows, for each display, which desktop it is showing and how many desktops it has.

```text
Built-in Retina Display: showing desktop 2 of 5; this display has 3 desktop(s)
Studio Display: showing desktop 4 of 5; this display has 2 desktop(s)
```

A display showing a native fullscreen app reads `showing a fullscreen Space`.

With `--json`, the document also lists every desktop, in Mission Control order:

```json
{
  "desktops" : [
    {
      "active" : true,
      "display" : "Built-in Retina Display",
      "number" : 1,
      "showing" : true,
      "windows" : [
        1187,
        1203
      ]
    },
    {
      "active" : false,
      "display" : "Built-in Retina Display",
      "number" : 2,
      "showing" : false,
      "windows" : [
        1320
      ]
    },
    {
      "active" : false,
      "display" : "Studio Display",
      "number" : 3,
      "showing" : true,
      "windows" : [

      ]
    }
  ],
  "displays" : [
    {
      "desktop" : 1,
      "desktopCount" : 2,
      "main" : true,
      "name" : "Built-in Retina Display"
    },
    {
      "desktop" : 3,
      "desktopCount" : 1,
      "main" : false,
      "name" : "Studio Display"
    }
  ]
}
```

| Key | Value |
| --- | --- |
| `desktops[].number` | The desktop's number, counted across all displays. |
| `desktops[].display` | The name of the display the desktop belongs to. `null` when the displays share their desktops ("Displays have separate Spaces" is off). |
| `desktops[].showing` | `true` when a display is showing this desktop. |
| `desktops[].active` | `true` for the desktop you are on: the one being shown on the display that has the focus. |
| `desktops[].windows` | The `id` of each window Iguana has seen on this desktop. Iguana learns of a window when its desktop is on screen, so a desktop you have not visited since Iguana started can read as empty. |
| `displays[].name` | The display's name. |
| `displays[].desktop` | The number of the desktop the display is showing, or `null` while it shows a fullscreen Space. |
| `displays[].desktopCount` | How many desktops the display has. |
| `displays[].main` | `true` for the main display. |

### `tree`

```text
tree
tree --json
```

Prints the layout tree of the desktop each display is showing. Containers are `horizontal`
(side by side) or `vertical` (stacked). The weight is each entry's share relative to its
siblings.

```text
Built-in Retina Display, desktop 1
  horizontal  [weight 1.00]
    - Safari: Start Page #1203  [weight 1.00]
    vertical  [weight 1.00]
      - Terminal: zsh #1187  [weight 1.00]
      - Notes: Notes #1320  (not on screen)  [weight 1.00]
```

If other desktops have a remembered layout, a last line says how many.

With `--json`, containers and windows nest in `children`:

```json
{
  "displays" : [
    {
      "desktop" : 1,
      "display" : "Built-in Retina Display",
      "layout" : {
        "children" : [
          {
            "app" : "Safari",
            "id" : 1203,
            "onScreen" : true,
            "title" : "Start Page",
            "type" : "window",
            "weight" : 1
          },
          {
            "children" : [
              {
                "app" : "Terminal",
                "id" : 1187,
                "onScreen" : true,
                "title" : "zsh",
                "type" : "window",
                "weight" : 1
              },
              {
                "app" : "Notes",
                "id" : 1320,
                "onScreen" : false,
                "title" : "Notes",
                "type" : "window",
                "weight" : 1
              }
            ],
            "orientation" : "vertical",
            "type" : "container",
            "weight" : 1
          }
        ],
        "orientation" : "horizontal",
        "type" : "container",
        "weight" : 1
      }
    }
  ],
  "otherLayouts" : 1
}
```

| Key | Value |
| --- | --- |
| `displays[].display` | The display's name. |
| `displays[].desktop` | The number of the desktop it is showing, or `null` for a fullscreen Space, which Iguana does not manage. |
| `displays[].layout` | The root of the layout tree, or `null` when the desktop has no tiled window. |
| `otherLayouts` | How many desktops that are not being shown have a remembered layout. |

Every entry of a layout has a `type` and a `weight`, its share relative to the entries beside
it. The other keys depend on the type:

| `type` | Keys |
| --- | --- |
| `container` | `orientation`, which is `horizontal` (side by side) or `vertical` (stacked), and `children`. |
| `window` | `id`, `app`, `title` and `onScreen`. `app` and `title` are left out for a window Iguana remembers from before a restart and has not seen again yet. |

### `status`

```text
status
status --json
```

Shows whether Iguana is tiling, which config file is in use and any problems with it, how
many windows and apps it is watching, the state of Stage Manager, what each display is
showing, how many shortcuts are active, and the last shortcut it received with its answer.

```text
Iguana 0.1.2: tiling
config: /Users/you/.config/iguana/iguana.toml
windows: 3 tiled on screen, 7 known, 5 apps watched
stage manager: off
Built-in Retina Display: showing desktop 1 of 3; this display has 3 desktop(s)
shortcuts: 40 active
last shortcut: option-l, 4 s ago, answered "ok"
```

Config problems and shortcuts that could not be registered appear as indented `warning:`
lines. While the welcome tour is on screen, a `welcome tour:` line above the last one says
so. Before the permission is granted, `status` says that Iguana is waiting for it.

With `--json`:

```json
{
  "configExists" : true,
  "configPath" : "/Users/you/.config/iguana/iguana.toml",
  "configWarnings" : [

  ],
  "displays" : [
    {
      "desktop" : 1,
      "desktopCount" : 3,
      "main" : true,
      "name" : "Built-in Retina Display"
    }
  ],
  "lastShortcut" : {
    "keys" : "option-l",
    "reply" : "ok",
    "secondsAgo" : 4
  },
  "paused" : false,
  "permission" : true,
  "shortcuts" : {
    "active" : 40,
    "warnings" : [

    ]
  },
  "stageManager" : {
    "on" : false,
    "reserved" : 0
  },
  "tourShowing" : false,
  "version" : "0.1.2",
  "windows" : {
    "apps" : 5,
    "known" : 7,
    "tiled" : 3
  }
}
```

| Key | Value |
| --- | --- |
| `version` | Iguana's version. |
| `permission` | `true` when Iguana has the Accessibility permission. |
| `paused` | `true` while tiling is paused. |
| `configPath` | Where the config file lives. |
| `configExists` | `false` when there is no file there and the built-in defaults are in use. |
| `configWarnings` | The problems in the config file, one string each. |
| `windows` | `tiled` counts the windows tiled on screen, `known` every window Iguana knows about, `apps` the apps it is watching. |
| `stageManager` | `on`, and `reserved`: the points left free for the strip of recent apps. |
| `displays` | The same list as in [`list-spaces --json`](#list-spaces). |
| `shortcuts` | `active` is how many shortcuts are registered. `warnings` lists the ones that could not be. |
| `tourShowing` | `true` while the welcome tour is on screen. |
| `lastShortcut` | The last shortcut received: its `keys`, how many `secondsAgo`, and the `reply` it got. `null` when none has been received since Iguana started. |
