This page lists every setting Iguana has: its type, default, allowed values and what it does.
The complete default file is [at the end](#the-default-file).

## The file

Iguana reads one file, written in [TOML](https://toml.io/):

```text
~/.config/iguana/iguana.toml
```

If the `XDG_CONFIG_HOME` environment variable is set, the file is
`$XDG_CONFIG_HOME/iguana/iguana.toml` instead. `iguana config path` prints the location in use.

**You do not need a config file.** With no file, the built-in defaults apply.

### Create it

```sh
iguana config init
```

This writes two files and leaves an existing config untouched:

<FileTree>

- ~/.config/iguana/
  - iguana.toml the default config, ready to edit
  - iguana.schema.json describes the file to your editor

</FileTree>

### How the file is applied

- **Every setting is optional.** Your file is laid over the built-in defaults. Anything you
  leave out keeps its built-in value.
- **Shortcuts are merged one by one.** Each entry in `[bindings]` is laid over the built-in
  shortcuts. Leave a shortcut out to keep it. Set it to `""` or `false` to switch it off.
- **Rules are the exception.** Once a file has any `[[rule]]`, it lists all of the rules. The
  built-in rules no longer apply unless they are in the file.
- **The file is reloaded when you save it.** `iguana reload` does the same on request.

The [settings window](/guides/settings-window/) edits this same file.

### When the file has a mistake

A broken file never stops Iguana.

- **A syntax error** means the file cannot be read as TOML. Iguana reports it with its line
  number and keeps the settings it had before.
- **A smaller problem** is a warning: an unknown key, a value out of range, a value of the
  wrong type, a shortcut or command it cannot parse. That one setting keeps its default and
  everything else in the file is applied.

Problems are shown by `iguana status`, in the General pane of the settings window and in the
log. The menu bar item's menu says how many there are. To check a file without loading it:

```sh
iguana config check                 # the file Iguana uses
iguana config check path/to/file    # any other file
```

`config check` prints every problem. It exits with a non-zero status only if the file cannot
be loaded at all. If there is no file, it says that the built-in settings apply.

### Completion and validation in your editor

The first line of the default file is:

```toml
#:schema ./iguana.schema.json
```

Editors with TOML support read that line and use the schema beside the config file to offer
completion, help on hover and validation as you type. Taplo and the "Even Better TOML"
extension for VS Code both do.

The same schema is published with these docs at
[`/schema/iguana.schema.json`](/schema/iguana.schema.json).

## `[gaps]`

Empty space around and between tiled windows, in points.

```toml title="iguana.toml"
[gaps]
inner = 8
outer = 8            # or: outer = { top = 8, left = 8, bottom = 8, right = 8 }
```

### `inner`

Space between neighbouring windows.

| | |
| --- | --- |
| Type | number |
| Default | `8` |
| Allowed | 0 to 200 |

### `outer`

Space between the windows and the edge of the area macOS leaves for windows, which is the
screen minus the menu bar and the Dock.

| | |
| --- | --- |
| Type | number, or a table with `top`, `left`, `bottom` and `right` |
| Default | `8` |
| Allowed | 0 to 500, for the single number and for each side |

One number sets all four sides. A table sets sides individually. A side you leave out of the
table keeps the default.

```toml title="iguana.toml"
[gaps]
outer = { top = 4, left = 8, bottom = 8, right = 8 }
```

## `[layout]`

```toml title="iguana.toml"
[layout]
auto-split = true    # new windows split the focused window along its longer side
resize-step = 0.05   # share of the container that one `resize` step moves
stack-peek = 32      # points of each window in a stack that stay visible behind the front one
mouse-follows-focus = false
focus-follows-mouse = false   # the window the pointer rests on gets the focus
```

### `auto-split`

When `true`, a new window splits the focused window along its longer side. When `false`, it
is added to the focused window's row or column.
[How tiling works](/guides/how-tiling-works/#where-a-new-window-opens) shows both.

| | |
| --- | --- |
| Type | boolean |
| Default | `true` |

### `resize-step`

The share of the container that one `resize grow` or `resize shrink` moves. `0.05` is five
percent.

| | |
| --- | --- |
| Type | number |
| Default | `0.05` |
| Allowed | greater than 0, up to 0.5 |

### `stack-peek`

How much of each window in a [stack](/guides/how-tiling-works/#stack) stays visible behind the
window in front, in points. Every window of a stack is shifted this far from the one before
it. In a stack with too little room for all its strips, they get narrower so that the window
in front keeps at least half of the stack.

| | |
| --- | --- |
| Type | number |
| Default | `32` |
| Allowed | 8 to 120 |

### `mouse-follows-focus`

When `true`, Iguana moves the pointer to the centre of a window when a shortcut focuses it.

| | |
| --- | --- |
| Type | boolean |
| Default | `false` |

### `focus-follows-mouse`

When `true`, the window the pointer comes to rest on gets the focus, without a click. The
pointer has to lie still on the window for a moment, about 80 milliseconds, so the windows
you only pass over are left alone.

| | |
| --- | --- |
| Type | boolean |
| Default | `false` |

- **Standard windows only.** Tiled or floating, on any display. The window comes to the
  front, as it does for the [`focus`](/reference/commands/#focus) command.
- **Never while a mouse button is down.** Dragging, resizing and selecting are left alone.
- **Never over anything else.** Not over the menu bar, the Dock, the desktop, a menu, a
  popover or a dialog, and not while a menu is open anywhere.
- **Never onto a window that is covered where the pointer is.** The window in front at that
  point is the one under the pointer.
- **The keyboard is not overruled.** After a shortcut, or anything else that is not the
  pointer, moved the focus, nothing happens until you move the pointer again, by more than a
  few points. A pointer that happens to lie on another window does not take the focus back.
- **It works with [`mouse-follows-focus`](#mouse-follows-focus).** When a shortcut takes the
  pointer along to the window it focused, that does not count as you moving it.
- **It is about focus, not tiling.** It keeps working while tiling is paused.

While this is off, Iguana does not listen to the pointer at all.

## `[animation]`

How windows travel to their new place. Animation is switched off automatically while macOS's
Reduce Motion setting is on. The [Animation guide](/guides/animation/) has the background.

```toml title="iguana.toml"
[animation]
enabled = true       # windows glide to their new place instead of jumping
duration = 0.16      # seconds, 0.05 to 1
easing = "ease-out"  # "linear", "ease-out" or "ease-in-out"
```

### `enabled`

When `true`, windows glide to their new place. When `false`, they jump.

| | |
| --- | --- |
| Type | boolean |
| Default | `true` |

### `duration`

Seconds a window takes to reach its new place.

| | |
| --- | --- |
| Type | number |
| Default | `0.16` |
| Allowed | 0.05 to 1 |

### `easing`

How the motion is paced.

| | |
| --- | --- |
| Type | string |
| Default | `"ease-out"` |
| Allowed | `"linear"`, `"ease-out"`, `"ease-in-out"` |

## `[focus-ring]`

A ring around the window that has the focus, so that you can see at a glance which window
your typing goes to. It is off until you switch it on.

```toml title="iguana.toml"
[focus-ring]
enabled = false
width = 3            # points, 1 to 10
color = "accent"     # the system accent colour, or a colour such as "#8fd43f"
```

- **Tiled and floating windows both get it.** Any standard window can have the ring. Dialogs
  and sheets do not, and neither does a window in native fullscreen.
- **It lies outside the window.** The ring is drawn in the gap around the window and never
  covers what is in it. Its corners follow the corners of a macOS window. Where there is no
  gap, the ring lies over the edge of the neighbouring window, and a side at the very edge of
  the screen is off the screen.
- **It sits directly above the focused window,** not above everything. A window that lies
  over the focused one covers the ring too.
- **It steps aside while the window moves.** While a window glides to a new place, and while
  you drag or resize it, the ring is not drawn. It comes back where the window stops.
- **It is about focus, not tiling.** The ring stays while tiling is paused.
- **It marks the window Iguana's shortcuts act on.** When you click the desktop, or one of
  Iguana's own windows is in front, that is still the window in front of the others, and the
  ring stays on it.

### `enabled`

When `true`, Iguana draws the ring.

| | |
| --- | --- |
| Type | boolean |
| Default | `false` |

### `width`

How thick the ring is, in points.

| | |
| --- | --- |
| Type | number |
| Default | `3` |
| Allowed | 1 to 10 |

A ring wider than your [gaps](#gaps) reaches over the neighbouring windows.

### `color`

The colour of the ring.

| | |
| --- | --- |
| Type | string |
| Default | `"accent"` |
| Allowed | `"accent"`, or a colour written `"#rgb"`, `"#rrggbb"` or `"#rrggbbaa"` |

| Value | Effect |
| --- | --- |
| `"accent"` | The accent colour chosen in System Settings > Appearance. The ring follows it when you change it. |
| `"#8fd43f"` | A colour of your own, as red, green and blue in hexadecimal. `"#8d3"` is short for `"#88dd33"`. |
| `"#8fd43f80"` | The same with an opacity as a fourth pair of digits: `80` is about half see-through. |

Anything else is a warning, and the ring keeps the accent colour.

## `[stage-manager]`

Room for Stage Manager's strip of recent apps. These settings do nothing while Stage Manager
is off. The [Stage Manager guide](/guides/stage-manager-fullscreen-tabs/#stage-manager)
explains the behaviour.

```toml title="iguana.toml"
[stage-manager]
# "auto" leaves room for the strip of recent apps while Stage Manager shows it.
# Use true to always leave room, false to tile underneath it, or a number of points to reserve.
reserve-strip = "auto"
strip-width = 150
```

### `reserve-strip`

| | |
| --- | --- |
| Type | the string `"auto"`, a boolean, or a number |
| Default | `"auto"` |
| Allowed | `"auto"`, `true`, `false`, or a number from 0 to 600 |

| Value | Effect |
| --- | --- |
| `"auto"` | Leave `strip-width` points free while Stage Manager is on and its strip is set to stay visible. |
| `true` | Leave `strip-width` points free whenever Stage Manager is on. |
| `false` or `0` | Leave no room. Windows are tiled underneath the strip. |
| a number | Leave that many points free whenever Stage Manager is on. |

### `strip-width`

The width, in points, used when `reserve-strip` is `"auto"` or `true`.

| | |
| --- | --- |
| Type | number |
| Default | `150` |
| Allowed | 0 to 600 |

## `[menu-bar]`

What the menu bar item draws.

```toml title="iguana.toml"
[menu-bar]
desktops = "current"
click-to-switch = false
```

### `desktops`

Which desktops the icon in the menu bar draws. Each desktop is drawn as its layout: one
block for each tiled window, in the place the window has on screen.

| | |
| --- | --- |
| Type | string |
| Default | `"current"` |
| Allowed | `"current"`, `"all"`, `"occupied"` |

| Value | Effect |
| --- | --- |
| `"current"` | Draw the desktop you are on. |
| `"all"` | Draw every desktop side by side, in Mission Control order. An empty desktop is an outline. |
| `"occupied"` | Draw every desktop that has tiled windows, and the one you are on. |

With `"all"` or `"occupied"`:

- The desktop you are on is drawn at full strength with a mark under it. The others are faint.
- The windows of a desktop you are not on are drawn as Iguana last knew them. A window that
  was minimised or hidden there still shows.
- A click anywhere on the item opens its menu, unless
  [`click-to-switch`](#click-to-switch) is on.
- While tiling is paused, or when there is only one desktop to draw, the item is the single
  drawing again.

The item takes more room in the menu bar, about 23 points for each desktop drawn.

### `click-to-switch`

Whether a click on a desktop drawn in the menu bar goes to that desktop. It only matters
while `desktops` is `"all"` or `"occupied"`.

| | |
| --- | --- |
| Type | boolean |
| Default | `false` |

| Value | Effect |
| --- | --- |
| `false` | A click anywhere on the item opens its menu. |
| `true` | A click on another desktop goes to it. A click on the desktop you are on opens the menu. |

Either way, the menu itself has every desktop in it, and a click on one there goes to it.

## `[updates]`

Whether Iguana looks for a newer version of itself. It only ever looks and tells you: it
downloads nothing and installs nothing.

```toml title="iguana.toml"
[updates]
check = true
```

### `check`

Whether Iguana asks GitHub, about once a day, if a newer version has been released.

| | |
| --- | --- |
| Type | boolean |
| Default | `true` |

| Value | Effect |
| --- | --- |
| `true` | Iguana asks about twenty seconds after it starts, if a day has passed since it last asked, and then once every 24 hours while it runs. It remembers when it last asked, so restarting often does not mean asking often. |
| `false` | Iguana never asks by itself, and says nothing about versions in its menu or in `status`. [`iguana update`](/reference/commands/#update) and **Check Now** in the settings window still ask when you tell them to. |

When there is a newer version:

- The menu of the menu bar item gains one item, **Update to Iguana 0.2.2…** with the real
  number, above **Settings…**. Choosing it opens that release's page in your browser.
- [`status`](/reference/commands/#status) gains one line, and `status --json` an `update`.

There is no alert, no notification, no badge and no sound. You update Iguana the way you
installed it: see [Staying up to date](/start/install/#staying-up-to-date).

A check that cannot be made, because the Mac is offline or GitHub does not answer, changes
nothing you can see. It is written to the log once, and tried again a day later.

The request carries nothing about you or your Mac: no identifier, no cookie and no stored
credentials. It is one request for a public address that names itself `Iguana/0.2.1`, with
the version you are running, and nothing else of note.
[The one network request](/help/under-the-hood/#the-one-network-request) lists exactly what
is sent and what is read.

## `[hooks]`

Shell commands that Iguana runs when something changes, so that a status bar or a script of
your own can follow along. [Status bars and scripts](/guides/status-bars-and-scripts/) has a
worked example.

```toml title="iguana.toml"
[hooks]
desktop-changed = ""   # the desktop a display is showing changed
focus-changed = ""     # a different window has the focus
```

Hooks are set in the file only. The [settings window](/guides/settings-window/) has no pane
for them, and leaves a `[hooks]` section exactly as you wrote it.

### `desktop-changed`

Runs when the desktop a display is showing changed, however you got there: a shortcut, a
trackpad swipe, Mission Control, or a click in the Dock. It also runs when a display starts or
stops showing a fullscreen app, and when the desktop you are on gets another number because a
desktop before it was added or removed.

| | |
| --- | --- |
| Type | string, a shell command |
| Default | `""` |

### `focus-changed`

Runs when a different window has the focus, and when the last window on a desktop goes away
and no window has it any more. A window that only changes its title does not run it.

| | |
| --- | --- |
| Type | string, a shell command |
| Default | `""` |

An empty string, or a key you leave out, runs nothing.

### What the command is given

The facts arrive as environment variables.

| Variable | Value | Set for |
| --- | --- | --- |
| `IGUANA_EVENT` | `desktop-changed` or `focus-changed`. | both |
| `IGUANA_DESKTOP` | The number of the desktop, counted as Mission Control counts them. For `focus-changed` it is the desktop of the focused window. Empty for a fullscreen Space. | both |
| `IGUANA_DISPLAY` | The name of the display, such as `Built-in Retina Display`. | both |
| `IGUANA_WINDOW_ID` | The window's number, the `id` of [`list-windows --json`](/reference/commands/#list-windows). Empty when no window has the focus. | `focus-changed` |
| `IGUANA_APP` | The name of the window's app. | `focus-changed` |
| `IGUANA_TITLE` | The window's title at that moment. | `focus-changed` |

<Aside type="caution" title="Quote the variables">
A window title can be any text at all: a web page chooses the title of its browser window.
Iguana never writes a title, or any other fact, into the command it runs. They only ever
travel as environment variables, so nothing in them is run as code by Iguana.

Keep it that way in your own scripts. Write `"$IGUANA_TITLE"` with the double quotes, and
never pass it to `eval` or paste it into another command line.
</Aside>

A value longer than 4096 bytes is cut off there.

### How a command is run

- **With `/bin/sh -c`,** in your home folder, with the environment Iguana itself has plus the
  variables above. It has no terminal: it reads nothing, and what it prints is discarded.
- **Homebrew's folders are on its `PATH`.** An app opened from the Finder gets a short
  `PATH`, so Iguana adds `/opt/homebrew/bin` and `/usr/local/bin` at the end of it. For a
  program anywhere else, write its full path.
- **Iguana never waits for it.** A slow command does not slow down your windows.
- **One run of each hook at a time.** If a hook is still running when its event happens
  again, the newest event waits for the run to end and then runs once. Events in between are
  skipped, so a slow command cannot pile up, and what it hears last is always the latest
  state. With two displays that change at the same moment, that can mean a slow hook hears
  about only one of them.
- **Only on a real change.** The first look Iguana takes when it starts is not a change.
- **Not before tiling starts.** Nothing runs until the Accessibility permission is granted,
  or while the welcome tour of a first start is still on screen. Pausing tiling does not stop
  hooks.
- **Trouble goes to the log, once.** A command that ends with a status other than 0, or that
  cannot be started, is written to `~/Library/Logs/Iguana.log` the first time it happens.
  Iguana never shows an alert for a hook. Status 127 means the shell could not find the
  program.

A value that is not a string is a warning, and that hook stays off.

## `[bindings]`

Keyboard shortcuts. Each entry has a shortcut on the left and a command on the right.

```toml title="iguana.toml"
[bindings]
option-h = "focus left"
option-shift-1 = "move-to-space 1 --stay"
option-f = ""                # switches the built-in shortcut off
```

| | |
| --- | --- |
| Key | Modifiers and a key joined by dashes, such as `option-shift-h`. See [Key names](/reference/key-names/). |
| Value | A [command](/reference/commands/) as a string, or `""` or `false` to switch the shortcut off. |
| Default | The 43 [default shortcuts](/reference/default-shortcuts/). |

Entries are merged over the built-in shortcuts one by one, so you only write the ones you want
to change. [Customising shortcuts](/guides/shortcuts/) has worked examples.

A shortcut that cannot be used is a warning, and the others still work:

- the shortcut does not parse (unknown modifier, no modifier, no key),
- the command does not parse,
- the value is neither a string nor `false`,
- the same combination is written twice,
- the key name is not one Iguana knows,
- macOS refuses to register the combination, usually because another app owns it.

## `[[rule]]`

What to do with the windows of an app: keep them floating, send them to a desktop when they
first appear, or both. Each rule is its own `[[rule]]` section. Dialogs, sheets and fixed-size
windows float on their own and need no rule.

**The first rule that matches a window decides.** Rules are tried in the order they appear in
the file, so order matters. That one rule answers for floating and for the desktop: the rules
below it are not asked.
[Floating windows and rules](/guides/floating-windows/) explains matching in detail.

```toml title="iguana.toml"
[[rule]]
app = "com.apple.calculator"
float = true

[[rule]]
app = "com.tinyspeck.slackmacgap"
desktop = 3
```

<Aside type="caution">
Once the file has any `[[rule]]`, the built-in rules no longer apply by themselves. A file
that lists rules lists all of them.
</Aside>

A rule needs `app` or `title`. A rule with neither is skipped with a warning.

### `app`

A bundle identifier, matched exactly, or part of the app's name. Case is ignored.

| | |
| --- | --- |
| Type | string |
| Default | none |

### `title`

A regular expression matched against the window title. Case is ignored. A rule whose `title`
is not a valid regular expression is skipped with a warning.

| | |
| --- | --- |
| Type | string |
| Default | none |

### `float`

Whether matching windows float.

| | |
| --- | --- |
| Type | boolean |
| Default | `true` in a rule without `desktop`. A rule with `desktop` and no `float` says nothing about floating. |

A rule that only has `desktop` does not float its windows. They are tiled, or float on
their own if they are dialogs, as they would with no rule at all. Write `float = true` beside
`desktop` to do both.

`float = false` makes the rule an exception: windows that match it are tiled, even if a
rule further down would float them. Because the first matching rule decides, an exception
goes above the general rule it is an exception to.

```toml title="iguana.toml"
# Safari's windows float, except those whose title contains "Downloads".
[[rule]]
app = "com.apple.Safari"
title = "Downloads"
float = false

[[rule]]
app = "com.apple.Safari"
float = true
```

### `desktop`

The desktop a matching window is sent to when it first appears. You stay on the desktop you
are on, as with [`move-to-space N --stay`](/reference/commands/#move-to-space).

| | |
| --- | --- |
| Type | whole number |
| Default | none: the window stays on the desktop it opens on |
| Allowed | 1 to 16 |

Desktops are numbered the way Mission Control numbers them, across all displays.

```toml title="iguana.toml"
# Slack's windows open on desktop 3 and are tiled there.
[[rule]]
app = "com.tinyspeck.slackmacgap"
desktop = 3

# Music floats, on desktop 2.
[[rule]]
app = "com.apple.Music"
float = true
desktop = 2
```

- **It happens once for each window,** when the window opens while Iguana is running. A
  window you move somewhere else afterwards stays where you put it.
- **Windows that are already open are not moved,** neither when Iguana starts nor when the
  config is reloaded.
- **Only standard windows are sent:** the ones Iguana could tile. Dialogs, sheets and
  fixed-size windows stay with their app. A new tab stays with its window.
- **A desktop that does not exist** leaves the window where it is and writes a line to the log.
  So does a window macOS refuses to move.
- **It needs the system's window-management bridge** (recent macOS). Without it, a window can
  only be taken to another desktop by going there with it, and a rule never takes you
  anywhere: the rule's `desktop` is not applied, and the log says so once. See
  [Limitations](/help/limitations/#sending-a-window-to-another-desktop-depends-on-the-macos-version).

A rule whose `desktop` is not a whole number from 1 to 16 is skipped with a warning.
[Desktops and displays](/guides/desktops-and-displays/#open-an-apps-windows-on-a-desktop) has
more.

### Built-in rules

| `app` | Which app |
| --- | --- |
| `com.apple.systempreferences` | System Settings |
| `com.apple.calculator` | Calculator |
| `com.apple.ActivityMonitor` | Activity Monitor |

## The default file

This is exactly what `iguana config init` writes, and what Iguana uses when there is no file.

```toml title="~/.config/iguana/iguana.toml"
#:schema ./iguana.schema.json
# Iguana configuration. Changes are picked up as soon as the file is saved.
# Every setting is optional: anything left out keeps its built-in value.

[gaps]
inner = 8
outer = 8            # or: outer = { top = 8, left = 8, bottom = 8, right = 8 }

[layout]
auto-split = true    # new windows split the focused window along its longer side
resize-step = 0.05   # share of the container that one `resize` step moves
stack-peek = 32      # points of each window in a stack that stay visible behind the front one
mouse-follows-focus = false
focus-follows-mouse = false   # the window the pointer rests on gets the focus

[animation]
enabled = true       # windows glide to their new place instead of jumping
duration = 0.16      # seconds, 0.05 to 1
easing = "ease-out"  # "linear", "ease-out" or "ease-in-out"

# A ring around the window that has the focus, tiled or floating.
[focus-ring]
enabled = false
width = 3            # points, 1 to 10
color = "accent"     # the system accent colour, or a colour such as "#8fd43f"

[stage-manager]
# "auto" leaves room for the strip of recent apps while Stage Manager shows it.
# Use true to always leave room, false to tile underneath it, or a number of points to reserve.
reserve-strip = "auto"
strip-width = 150

[menu-bar]
# Which desktops the menu bar icon draws: "current" for the one you are on, "all" for every
# desktop side by side, or "occupied" to leave out the empty ones.
desktops = "current"
# With more than one desktop drawn, true makes a click on one of them go to it. A click on
# the desktop you are on still opens the menu.
click-to-switch = false

[updates]
# Once a day Iguana asks GitHub whether a newer version has been released, and says so in its
# menu. It sends nothing about you or this Mac, and downloads and installs nothing.
check = true

# Rules for the windows of an app. `app` is a bundle id or part of the app name, `title` is a
# regular expression. `float = true` keeps matching windows floating; dialogs, sheets and
# fixed-size windows float on their own. `desktop = 3` sends a matching window to desktop 3
# when it first appears, and leaves you where you are.
# Once the file has any [[rule]], the built-in rules below no longer apply by themselves.
# The first rule that matches a window decides, so an exception (float = false) goes above
# the general rule it is an exception to.
[[rule]]
app = "com.apple.systempreferences"
float = true

[[rule]]
app = "com.apple.calculator"
float = true

app = "com.apple.ActivityMonitor"
```
