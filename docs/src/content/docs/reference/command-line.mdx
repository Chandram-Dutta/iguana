This page describes the `iguana` command line tool: what each subcommand does, how commands
reach the running app, and what the exit codes mean.

The tool is the same binary that runs the app. It is inside the app bundle at
`Iguana.app/Contents/MacOS/iguana`. [Install](/start/install/) shows how to put it on your
`PATH`.

## Synopsis

```text
iguana daemon
iguana config init
iguana config path
iguana config check [file]
iguana settings
iguana tour
iguana update
iguana subscribe [event ...]
iguana help
iguana version
iguana <command>
iguana <command> --window ID
```

## Subcommands

### `iguana daemon`

Runs the window manager. This is what `Iguana.app` does when you open it, so you rarely need
to type it. If Iguana is already running, it prints `Iguana is already running.` and exits.

### `iguana config`

| Form | What it does |
| --- | --- |
| `iguana config init` | Writes the default config file, and `iguana.schema.json` beside it. An existing config file is left untouched. |
| `iguana config path` | Prints where the config file lives. |
| `iguana config check [file]` | Checks the config file, or the file you name, the way Iguana would load it, and prints every problem. |

These work whether or not Iguana is running. See
[Configuration](/reference/configuration/#the-file).

`config check` exits with status 0 when the file loads, with or without warnings, and also
when there is no file, in which case it says that the built-in settings apply. It exits with
status 1 when the file cannot be loaded because of a syntax error, or cannot be read.

### `iguana settings`

Opens the [settings window](/guides/settings-window/). This is the
[`settings`](/reference/commands/#settings) command, sent to the running app like any other,
so Iguana has to be running.

### `iguana tour`

Shows the [welcome tour](/start/install/#the-welcome-tour) again. This is the
[`tour`](/reference/commands/#tour) command, so Iguana has to be running.

### `iguana update`

Asks now whether a newer Iguana has been released, and prints one line: that yours is the
latest, or the newer version and the address of its page. This is the
[`update`](/reference/commands/#update) command, so Iguana has to be running: the running app
makes the request. It exits with status 1 when the check could not be made. It only asks: to
install a newer version, see [Staying up to date](/start/install/#staying-up-to-date).

### `iguana subscribe`

Stays connected to the running app and prints one line of JSON for each event, as it
happens: first the current state, then every change. This is the
[`subscribe`](/reference/commands/#subscribe) command, so Iguana has to be running.

```sh
iguana subscribe desktop-changed focus-changed
```

Each line is printed the moment it arrives, so it can be piped straight into a script. The
tool runs until Iguana quits, and then exits with status 0. Press Control-C to stop it
sooner. [Status bars and scripts](/guides/status-bars-and-scripts/#be-told-a-stream-of-events)
has an example.

### `iguana help`

Prints the usage text and the list of commands. `-h` and `--help` do the same.

### `iguana version`

Prints the version number. `--version` does the same.

### `iguana` with no arguments

In a terminal, prints the usage text. When the binary is launched as an app, with no terminal
attached, it runs the window manager.

## Sending commands

Anything else on the command line is sent to the running app as a
[command](/reference/commands/):

```sh
iguana focus left
iguana resize grow width
iguana move-to-space 3 --stay
iguana close --window 1402
iguana status
iguana list-windows --json
```

What happens:

1. The tool checks that the command is well formed. If it is not, it prints the reason and
   stops, without contacting the app.
2. It sends the command to the running app over a socket in your own Library folder,
   `~/Library/Application Support/Iguana/iguana.sock`. Only your user account can use it.
3. The app runs the command and sends back its reply, which the tool prints. For
   [`subscribe`](/reference/commands/#subscribe) the connection stays open instead, and the
   app sends a line for each event until it quits.

Because every command works this way, anything a shortcut can do can also be scripted.

### Flags

| Flag | On | What it does |
| --- | --- | --- |
| `--stay`, `--follow` | [`move-to-space`](/reference/commands/#move-to-space) | Send the window and stay, or go with it (the default). |
| `--json` | [`list-windows`](/reference/commands/#list-windows), [`list-spaces`](/reference/commands/#list-spaces), [`tree`](/reference/commands/#tree), [`status`](/reference/commands/#status) | Answer with one JSON document instead of text. See [JSON output](/reference/commands/#json-output). |
| `--window ID` | [The commands that act on a window](/reference/commands/#acting-on-another-window) | Act on the window with that id instead of the focused one. See [below](#acting-on-another-window). |

`--json` can come before or after the command. On any other command it is a mistake, and the
tool stops with exit code 2. The same goes for `--window`, which can come anywhere in the
line. The two cannot be combined.

### Acting on another window

A command acts on the focused window. To act on another one, name it with `--window` and its
id. The focus stays where it is. `iguana list-windows` prints the ids, and
[`jq`](https://jqlang.org) picks one out of the JSON form:

```sh
# The first Safari window.
id=$(iguana list-windows --json | jq -r 'first(.windows[] | select(.app == "Safari") | .id)')

# Send it to desktop 2, and stay where you are.
iguana move-to-space 2 --stay --window "$id"

# Close every Calculator window.
iguana list-windows --json | jq -r '.windows[] | select(.app == "Calculator") | .id' |
  while read -r id; do iguana close --window "$id"; done
```

The id is a whole number, the same one `list-windows` prints. It stays the same until the
window closes, so read it fresh each time the script runs. When the id is missing or is not
a number, the tool stops with exit code 2:

```text
iguana: --window needs a window id (see iguana list-windows)
```

When no window has that id, the reply is `error: no window ID` and the exit code is 1.
[Acting on another window](/reference/commands/#acting-on-another-window) in the command
reference lists the commands that take it and what each does with it.

To be told when something changes, instead of asking, see
[`subscribe`](/reference/commands/#subscribe) and [`[hooks]`](/reference/configuration/#hooks).

### Exit codes

| Code | Meaning |
| --- | --- |
| `0` | The reply did not start with `error`. This includes replies such as `ok: nothing in that direction`, every JSON document, and the end of `subscribe` when Iguana quits. |
| `1` | The reply started with `error`, or Iguana is not running. |
| `2` | The command was not well formed, so it was not sent. |

When Iguana is not running the tool prints:

```text
iguana: the window manager is not running (open Iguana.app or run `iguana daemon`)
```

## Diagnostics

| Command | Shows |
| --- | --- |
| [`iguana status`](/reference/commands/#status) | Whether Iguana is tiling, config problems, how many shortcuts are active, and the last shortcut received with its answer. |
| [`iguana list-windows`](/reference/commands/#list-windows) | Every window Iguana knows about and how it treats it. |
| [`iguana tree`](/reference/commands/#tree) | The layout tree of the desktops that are showing. |
| [`iguana list-spaces`](/reference/commands/#list-spaces) | Which desktop each display is showing. |

Each of the four takes `--json`.

The log is at `~/Library/Logs/Iguana.log`. To watch it:

```sh
tail -f ~/Library/Logs/Iguana.log
```

## Files Iguana uses

| Path | What it is |
| --- | --- |
| `~/.config/iguana/iguana.toml` | The config file. Optional. |
| `~/.config/iguana/iguana.schema.json` | The schema for editors. Iguana writes it beside the config file whenever it creates or changes that file: `iguana config init`, **Edit Config File** in the menu, or a change in the settings window. |
| `~/Library/Application Support/Iguana/state.json` | Saved layouts, so they survive a restart of Iguana or of the Mac. |
| `~/Library/Application Support/Iguana/iguana.sock` | The socket the command line tool talks to. It exists while Iguana runs. |
| `~/Library/Logs/Iguana.log` | The log. |
| `~/Library/Preferences/xyz.onlychan.iguana.plist` | Whether the welcome tour has been shown, when Iguana last looked for a newer version, and the newer version it found. |
