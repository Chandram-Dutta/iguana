After this page you will know which macOS interfaces Iguana uses, which of them are
undocumented, why none of it needs System Integrity Protection (SIP) switched off, and
exactly what Iguana says to the network.

## The one rule

Iguana only ever sets the frame of windows that macOS is showing right now. It never hides a
window, parks it off screen or moves it to build a workspace. Desktops, Mission Control,
Stage Manager, fullscreen and minimising stay the system's business.

Everything below follows from that rule.

## What happens when something changes

1. **Something changes.** An app launches or quits, a window opens, closes, moves, is
   minimised or restored, an app is hidden or shown, the desktop changes or a display is
   connected. macOS notifies Iguana.
2. **Iguana looks at what is on screen.** It asks the window server which windows are showing
   and where, and reads which desktop each display is on.
3. **It updates the layout trees.** New windows are added next to the last focused window.
   Windows that no longer exist are removed. Windows that exist but are not showing stay in
   the tree. In the first minutes after a restart of the Mac, a window that Iguana
   recognises from before takes its old place instead.
4. **It computes a frame for every visible tiled window** from the tree of the desktop each
   display is showing.
5. **It sets only the frames that differ** from where the windows already are.
6. **If a window refused its size,** Iguana records the size the window kept and repeats
   steps 4 and 5 once, around it.

Changes that arrive close together are handled in one pass. While you hold the mouse button
on a window, Iguana leaves that window alone until you let go.

## Documented interfaces

Most of Iguana is built on interfaces Apple documents.

| Interface | Used for |
| --- | --- |
| Accessibility | Reading and setting a window's position and size, being told when windows open, close, move or change, raising a window, pressing its close button. This is what the Accessibility permission allows. |
| Window list | Asking the window server which windows are on screen right now, and where. Needs no permission. |
| Hot-key service | Global shortcuts. Needs no extra permission, and only takes the exact combinations that are registered. |
| Workspace notifications | Being told when apps launch, quit, activate, hide and show, and when the desktop or the displays change. |
| Synthetic key events | Pressing Mission Control's shortcut to switch desktop. |
| Synthetic mouse events | Only in the fallback for sending a window to another desktop: holding the window by its title bar. |
| Mouse movement | Only while [`focus-follows-mouse`](/reference/configuration/#focus-follows-mouse) is on: hearing that the pointer moved, to tell when it has come to rest on a window. Needs no extra permission. |

Iguana also reads three system preferences: whether Stage Manager is on, whether its strip of
recent apps hides itself, and which side the Dock is on. It uses them to decide where to
leave room for the strip.

## Undocumented interfaces

These are the only undocumented system interfaces Iguana uses. Each one either reads information or asks
the system to do something it already offers you.

| Name | What it does | Kind |
| --- | --- | --- |
| `_AXUIElementGetWindow` | Gives the window server's number for a window that Accessibility describes, so the two views of a window can be matched. | Read |
| `SLSMainConnectionID` | Gives Iguana's own connection to the window server, which the next two calls need. | Read |
| `SLSCopyManagedDisplaySpaces` | Lists each display, the desktop it is showing and all of its desktops in Mission Control order. | Read |
| `SLSCopySpacesForWindows` | Says which desktop a window is on. | Read |
| `CGSGetSymbolicHotKeyValue`, `CGSIsSymbolicHotKeyEnabled` | Look up which keys a Mission Control shortcut is set to, and whether it is switched on. | Read |
| `CGSSetSymbolicHotKeyEnabled` | Switches a Mission Control shortcut on for half a second when it was off, so that pressing it works, then switches it off again. | Request |
| `GetProcessForPID`, `_SLPSSetFrontProcessWithOptions`, `SLPSPostEventRecordTo` | Bring one specific window to the front without raising the app's other windows. | Request |
| `SLSBridgedMoveWindowsToManagedSpaceOperation` | Asks the system's window-management bridge to put a window on another desktop. | Request |

<Aside type="caution">
Undocumented means Apple can change these without notice. The read-only calls have been
stable for many macOS releases. The window-management bridge is newer: Iguana checks that it
is present before using it and falls back to the title bar method when it is not, or when a
window does not arrive.
</Aside>

## Why SIP is not needed

System Integrity Protection stops software from modifying protected parts of macOS,
including the system's own running processes.

Iguana does not need to get past it, because it never changes how the system works:

- **It does not inject code into any system process.** Everything runs inside Iguana's own
  process.
- **It hides nothing.** macOS already decides which windows show on each desktop. Iguana
  reads that decision instead of overriding it.
- **It switches desktops the way you do,** by pressing Mission Control's shortcut.
- **It moves a window to another desktop the way the system does,** through the system's own
  bridge on recent macOS, or the way you would by hand on older systems.

The only permission Iguana asks for is Accessibility.

## What Iguana says to the network

Iguana holds the Accessibility permission, so it owes you a plain account of what it says to
the network. It makes two kinds of request and no other:

- **The check.** About once a day it asks GitHub whether a newer version of Iguana has been
  released.
- **The download.** When you choose **Update to Iguana…** in its menu, it downloads that
  release from GitHub. It downloads a release by itself only if you switched on
  [`install`](/reference/configuration/#install), which is off to begin with.

**Neither request carries anything about you or your Mac: no identifier, no cookie and no
stored credentials. Each is made in a session that starts empty and is thrown away with the
answer, and names itself `Iguana/0.3.0`, with the version you are running, and nothing else
of note.**

### The check

It gives up after ten seconds. In detail:

| | |
| --- | --- |
| What is asked | `GET https://api.github.com/repos/Chandram-Dutta/iguana/releases/latest`, GitHub's public description of the latest release. The address is the same for everyone and needs no account. |
| What is sent | Three things, beyond what every web request carries: `User-Agent: Iguana/0.3.0`, `Accept: application/vnd.github+json` and `Accept-Language: en`. The last is fixed so that the languages chosen in System Settings are not sent. Nothing about your windows, apps, settings or Mac is in the request. |
| What GitHub sees | What any server sees: the internet address the request comes from, and the three lines above. |
| What is read | Four fields of the answer: the release's tag, the address of its page, and whether it is a draft or a prerelease. |
| What counts as newer | A release that is neither a draft nor a prerelease, with a tag that is a version greater than yours. Versions are compared number by number, so `0.1.10` is newer than `0.1.9`. A tag that is not a version is ignored. |
| What happens then | One item in the menu of the menu bar item, one line in `iguana status`. No alert, notification, badge or sound. Nothing is downloaded until you choose that item, unless you switched on [`install`](/reference/configuration/#install). |
| What is opened | Nothing, unless an install you chose fails. Then the release's page opens in your browser, and only if that address is `https`, on `github.com` and inside Iguana's repository. For anything else Iguana opens the repository's list of releases. The button in the settings window opens the same page. |
| When | About twenty seconds after Iguana starts, if a day has passed since it last asked, and then once every 24 hours while it runs. A check that fails is written to the log once and tried again a day later. |
| Redirects | Followed only to `api.github.com` over `https`. Any other is treated as a check that failed. |

To switch it off, turn off **Check for updates** in the General pane of the
[settings window](/guides/settings-window/#general), or set
[`check`](/reference/configuration/#check) in the config file:

```toml title="iguana.toml"
[updates]
check = false
```

With that, Iguana makes no request at all unless you ask for one with
[`iguana update`](/reference/commands/#update) or **Check Now** in the settings window. It
learns of no update, so it offers none and downloads none, whatever `install` says.

### The download

Nothing is downloaded until you choose **Update to Iguana…** in the menu. With
[`install = true`](/reference/configuration/#install), the same download starts by itself
when the daily check finds a newer version.

| | |
| --- | --- |
| What is asked | `GET https://github.com/Chandram-Dutta/iguana/releases/download/v0.3.1/Iguana-0.3.1.zip`, with the real number: the zip that release publishes. Iguana makes this address itself from the version number. No address from GitHub's answer to the check is ever downloaded. |
| What is sent | `User-Agent: Iguana/0.3.0`, `Accept: application/octet-stream` and `Accept-Language: en`. Nothing about your windows, apps, settings or Mac is in the request. |
| Who sees it | GitHub, and the host GitHub keeps release files on, which GitHub sends the download on to. Each sees what any server sees: the internet address the request comes from, and the three lines above. |
| Redirects | Followed only over `https`. Any other is treated as a download that failed. |
| Limits | A download of more than 200 MB is stopped and thrown away. So is one that is silent for thirty seconds, or takes more than ten minutes. |
| Where it is kept | In a temporary folder that only you can read, on the disk Iguana.app is on. The folder is removed when the install ends, whether it worked or not. |
| What is checked | The unpacked app, by macOS's code signing, on your Mac. It must satisfy the same requirement macOS uses to recognise the Iguana you already have, which means it is signed by the same developer. It must be notarized by Apple. Every file in it must match its signature. It must call itself `xyz.onlychan.iguana`, and be the version that was asked for. |
| What is trusted | Only that check. Not the address, not the server and not the connection: a download from anywhere is installed if and only if it passes. One that does not pass is thrown away, and nothing on your Mac is changed. |
| What happens then | The new app takes the place of the old one in one move, and Iguana restarts. Your windows stay where they are. Your Accessibility permission carries over, because macOS sees the same app. |
| What never happens | Iguana never asks for an administrator's password and never runs an installer. If you may not replace Iguana.app as yourself, it says so and opens the release's page. It never installs a version that is not newer than the one running. A copy that is not a released build, such as one you built yourself, does not update itself. |
| When it starts by itself | Only with `install = true`, only for a version the daily check found, and never while the welcome tour is on screen or a window is being dragged. A version that could not be installed is tried again a day later. |

Each step is written to the log, in lines that start with `update:`. When an install fails,
[`iguana status`](/reference/commands/#status) says why.

## What is stored on disk

| Path | Contents |
| --- | --- |
| `~/.config/iguana/iguana.toml` | Your settings. Optional. |
| `~/Library/Application Support/Iguana/state.json` | The layout tree of each desktop, the windows you floated or tiled by hand and the minimum sizes Iguana has learned, with the app, title and frame of each of those windows. Written about a second after the layout changes and again when Iguana quits. |
| `~/Library/Application Support/Iguana/iguana.sock` | The socket for the command line tool, `iguana subscribe` included — it keeps its connection open and is sent one line per event. Readable and writable only by you. |
| `~/Library/Logs/Iguana.log` | The log. |
| `~/Library/Preferences/xyz.onlychan.iguana.plist` | Whether the welcome tour has been shown, when Iguana last looked for a newer version, the newer version it found, and when it last tried to install one by itself. |
| A folder in your temporary items | The download of an update, and the app unpacked from it, while an install runs. Readable only by you, and removed when the install ends. |

When Iguana restarts, the saved state is used again as it is. The numbers that identify
windows start over when the Mac restarts, so after that Iguana goes by each window's app,
title and frame instead. For three minutes after tiling starts, a window that comes back
takes the place of the saved window of the same app with the same title. Failing that, it
takes the place of the nearest saved window of its app. The saved minimum sizes are not
used after a restart of the Mac.

That is why the file holds your window titles. It stays on your Mac: Iguana never sends it
anywhere.

## Staying responsive

- **A busy app cannot stall Iguana.** Each request to an app has a short time limit. An app
  that does not answer in time is skipped for that pass.
- **Focus requests are checked.** macOS sometimes reports that a window was focused and
  leaves the focus where it was. Iguana checks shortly afterwards and tries again.
- **Animation runs per app.** Each app's windows are driven on a separate background queue,
  frames are paced by the display's refresh, and frames an app cannot keep up with are
  dropped. See [Animation](/guides/animation/#how-it-stays-smooth).
- **A subscriber cannot stall Iguana.** A `subscribe` that stops reading its lines is let go
  once 256 lines are waiting for it.
- **A hook cannot stall Iguana.** The commands under
  [`[hooks]`](/reference/configuration/#hooks) are the only other programs Iguana starts.
  They are started off the main thread and never waited for, one run of each at a time. What
  they are told travels in environment variables and is never written into the command.
