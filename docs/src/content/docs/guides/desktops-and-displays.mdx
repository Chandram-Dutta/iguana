After this page you will be able to switch desktops, send windows between desktops and
displays, move the focus from one display to another, have an app's windows open on a desktop
you choose, and know how desktops and displays are numbered.

## Each desktop has its own layout

macOS lets you keep several desktops and switch between them. Apple's name for a desktop is a
Space. These docs say "desktop"; in command names you will see `space`, which means the same
thing.

Iguana does not add a workspace system of its own. Each desktop on each display has its own
layout, and Iguana tiles whichever desktops are showing. The layouts of desktops that are not
showing are remembered and are waiting when you come back.

The menu bar item shows the number of the desktop you are on, and its menu shows every
desktop with its layout. Click one there to go to it.

## How desktops are numbered

Desktops are numbered the way Mission Control names them: "Desktop 1", "Desktop 2" and so on.
With more than one display the count runs across all displays. If the first display has
three desktops, the first desktop of the second display is desktop 4.

`iguana list-spaces` shows what each display is showing:

```sh
iguana list-spaces
```

```text
Display 1, Built-in Retina Display: showing desktop 2 of 5; this display has 3 desktop(s)
Display 2, Studio Display: showing desktop 4 of 5; this display has 2 desktop(s)
```

The display names and numbers above are an example. Yours will differ.

## How displays are numbered

Displays have numbers of their own, which `focus-display` and `move-to-display` take. They are
counted from 1, left to right by the left edge of each display, the way you have arranged them
under Displays in System Settings. Where two displays share a left edge, the upper one comes
first.

The main display, the one with the menu bar, is not always display 1. With a monitor on the
left of a laptop, the monitor is display 1 and the laptop display 2. `iguana list-spaces`
starts each line with the number, as above.

## Switch desktop

| Keys | Command | What it does |
| --- | --- | --- |
| <kbd>option</kbd>+<kbd>1</kbd> to <kbd>option</kbd>+<kbd>9</kbd> | `space 1` to `space 9` | Go to that desktop. |
| <kbd>option</kbd>+<kbd>]</kbd> | `space next` | Go to the next desktop. |
| <kbd>option</kbd>+<kbd>[</kbd> | `space prev` | Go to the previous desktop. |
| <kbd>option</kbd>+<kbd>shift</kbd>+<kbd>tab</kbd> | `space recent` | Go back to the desktop you were on before. |

`space` accepts numbers from 1 to 16.

`space recent` goes back to the desktop the display showed before, however you left it:
with a shortcut, a swipe or Mission Control. Press it again to return, so two desktops you
use together are one key apart. Iguana remembers each display's desktops by the desktop
itself, not its number, so adding or removing desktops does not confuse it. Fullscreen Spaces
are skipped.

Iguana switches by pressing Mission Control's own shortcut for you: "Switch to Desktop N", or
"Move left a space" and "Move right a space" for `prev` and `next`. `recent` presses "Switch
to Desktop N" for the desktop it goes back to. That has three effects:

- It works whatever keys you gave those shortcuts in System Settings, and also when they are
  switched off there. Iguana switches a disabled shortcut on just long enough to fire it.
- macOS plays its slide animation. Turn on Reduce Motion (System Settings, Accessibility,
  Display) to shorten it to a fade.
- Gestures, Mission Control and the system's own shortcuts keep working. Whichever way you
  switch, Iguana sees the same result.

If you ask for a desktop that does not exist, Iguana answers, for example,
`error: there are only 3 desktops`. Create desktops in Mission Control.

## Send a window to another desktop

| Keys | Command | What it does |
| --- | --- | --- |
| <kbd>option</kbd>+<kbd>shift</kbd>+<kbd>1</kbd> to <kbd>option</kbd>+<kbd>shift</kbd>+<kbd>9</kbd> | `move-to-space 1` to `move-to-space 9` | Take the focused window to that desktop and go with it. |
| not bound | `move-to-space N --stay` | Send the window there and stay where you are. |
| <kbd>option</kbd>+<kbd>shift</kbd>+<kbd>]</kbd>, <kbd>option</kbd>+<kbd>shift</kbd>+<kbd>[</kbd> | `move-to-space next`, `move-to-space prev` | Take it to the next or previous desktop on the same display. `--stay` works here too. |
| not bound | `move-to-space recent` | Take it to the desktop you were on before. `--stay` works here too. |

With `--stay`, the focus goes to the window nearest to where the sent window was.

A window that arrives on a desktop joins the layout there like a newly opened window: it
splits the window that was last focused on that desktop.

If the desktop you name is on another display, the window is moved to that display.

### Two routes, depending on your macOS

On recent macOS (tested on 27.2), Iguana asks the system's own window-management bridge to
move the window. That takes a few milliseconds.

On systems without the bridge, or for a window the bridge refuses, Iguana falls back to doing
what you would do by hand: it holds the window by its title bar and switches desktop. The
fallback is slower, briefly takes over the mouse pointer, and always follows the window, so
`--stay` has no effect.

<Aside>
When the fallback is used, the log says so. See
[Troubleshooting](/help/troubleshooting/#sending-a-window-to-another-desktop-is-slow).
</Aside>

A window in a native fullscreen Space cannot be sent to another desktop.

## Open an app's windows on a desktop

A [rule](/guides/floating-windows/#rules) with a `desktop` sends the windows it matches to
that desktop as they open, so an app can have a desktop of its own:

```toml title="iguana.toml"
[[rule]]
app = "com.tinyspeck.slackmacgap"
desktop = 3
```

The bundle identifier here is Slack's, as an example. The **Window Rules** pane of the
[settings window](/guides/settings-window/#window-rules) has the same choice as a pop-up
menu on each rule.

When a matching window opens, Iguana sends it to desktop 3 and you stay where you are, as
with `move-to-space 3 --stay`. If the new window had the keyboard, the window you were using
before gets it back. The sent window joins the layout of desktop 3 the next time that desktop
is shown.

- **Once for each window.** A window is sent when it opens. Move it to another desktop
  afterwards and it stays there.
- **Nothing moves at launch.** Windows that are already open when Iguana starts, or when the
  config is reloaded, stay where they are. The rule acts on windows that open after that.
- **Only standard windows.** Dialogs, sheets and fixed-size windows are not sent anywhere. A
  new tab stays with the window it is a tab of.
- **While tiling is paused, nothing is sent,** and a window that opened during the pause is
  not sent afterwards.
- **A desktop that does not exist** leaves the window where it is. The log gets a line such
  as `rule: window 1187 of Slack was not sent to desktop 5: there are only 3 desktops`.
  Create desktops in Mission Control.
- **The first rule that matches a window decides** whether it floats and where it goes. See
  [Floating windows and rules](/guides/floating-windows/#send-an-apps-windows-to-a-desktop).

<Aside type="caution" title="Needs the system's window-management bridge">
A rule only sends a window where it can do so without taking you along. That needs the quick
route described under [Two routes](#two-routes-depending-on-your-macos). On a macOS without
it, the fallback always follows the window, so Iguana does not use it for rules: the window
stays where it opened, and the log says once that rules with a desktop are not applied.
</Aside>

A rule cannot send a window to a particular display. A desktop belongs to a display, so
naming a desktop on another display does move the window there.

## More than one display

Each display has its own layout for each of its desktops.

`move-to-space next` and `move-to-space prev` count along the desktops of the current
display. That is the display holding the focused tiled window, or the display under the
pointer when the focused window is not tiled.

### Move the focus and windows between displays

| Keys | Command | What it does |
| --- | --- | --- |
| <kbd>option</kbd>+<kbd>.</kbd> | `focus-display next` | Focus a window on the next display. |
| <kbd>option</kbd>+<kbd>,</kbd> | `focus-display prev` | Focus a window on the previous display. |
| <kbd>option</kbd>+<kbd>shift</kbd>+<kbd>.</kbd> | `move-to-display next` | Take the focused window to the next display. |
| <kbd>option</kbd>+<kbd>shift</kbd>+<kbd>,</kbd> | `move-to-display prev` | Take the focused window to the previous display. |
| not bound | `focus-display N`, `move-to-display N` | The same, for display `N`. |

`next` and `prev` follow the [display numbers](#how-displays-are-numbered), counted from the
display that holds the focused window, and wrap around: after the last display comes the
first.

`focus-display` focuses the window that last had the focus on that display. If that window is
gone, it focuses the tiled window nearest the middle of the display, or else a floating one.
On a display with no window, nothing gets the focus. With
[`mouse-follows-focus`](/reference/configuration/#mouse-follows-focus) on, the pointer moves to
the middle of that display, so a click lands there.

`move-to-display` keeps the focus on the window it takes. A tiled window joins the layout of
the desktop the other display is showing, beside the window last focused there. A floating
window stays floating, keeps its size where it fits, and lands in the same place in
proportion: against the same edge, or in the middle.

A display that is showing a native fullscreen app takes no windows. `move-to-display` answers,
for example, `error: display 2 is showing a fullscreen app`.

### Other ways across

- **Move a window to another display** with `move` in that direction. When the window is
  already at the edge of its layout, the next `move` carries it onto the display on that
  side. <kbd>option</kbd>+<kbd>shift</kbd>+<kbd>l</kbd> on the rightmost window sends it to the
  display on the right.
- **Drag a window** to another display with the mouse. Dropped on a tile there, it lands where
  the outline shows. Dropped anywhere else, it joins the layout of the display that holds its
  centre.
- **Focus across displays** with the `focus` commands. Focus goes by where windows are on
  screen, so <kbd>option</kbd>+<kbd>l</kbd> on the rightmost window of one display reaches the
  nearest window on the display to its right.

`move-to-space next` and `move-to-space prev` count along the desktops of the current
display. That is the display holding the focused tiled window, or the display under the
pointer when the focused window is not tiled. Each display remembers its own desktops, and
`space recent` and `move-to-space recent` go back to the one the current display showed
before.


### Displays that share desktops

macOS has a setting called "Displays have separate Spaces". When it is off, all displays
switch desktops together. Iguana still keeps a separate layout for each display on each
desktop.

## Fullscreen Spaces are left alone

When an app is in native fullscreen it gets a Space of its own. Iguana does not manage those:
it does not tile a display while that display is showing a fullscreen Space. See
[Stage Manager, fullscreen and tabs](/guides/stage-manager-fullscreen-tabs/).
