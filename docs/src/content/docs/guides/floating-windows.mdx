After this page you will know which windows Iguana tiles, how to take a window out of the
layout, how to put a floating window in a half, a quarter or the middle of the screen from the
keyboard, and how to write a rule so that an app's windows always float, open at a size and
place of your choice, or open on a desktop of your choice.

A **floating** window is one Iguana does not tile. It stays where you put it, at the size
you gave it, and the tiled windows ignore it. Iguana only moves it when you ask: with
`place`, or with a rule that says where it opens.

## What gets tiled

Iguana tiles a window when all of these are true:

- It belongs to a regular app, meaning one that appears in the Dock. Menu bar extras and
  background helpers are not watched at all.
- It is a standard window, not a dialog or a sheet.
- It can be both moved and resized. Fixed-size windows are left alone.
- It is not in native fullscreen.
- No rule floats it and you have not floated it yourself.

Everything else is left exactly as the app shows it. You do not need rules for open and save
dialogs, preference sheets or alerts.

`iguana list-windows` shows how Iguana sees each window it knows about:

| State | Meaning |
| --- | --- |
| `tiled` | In the layout. |
| `floating` | Could be tiled, but a rule or the `float` command keeps it out. |
| `unmanaged` | Not a standard, resizable window. Iguana will never tile it. |
| `not on screen` | Minimised, hidden, on another desktop, in another stage or a background tab. |

The focused window is marked with `*`.

## Float a window by hand

Press <kbd>option</kbd>+<kbd>shift</kbd>+<kbd>space</kbd>, or run `iguana float`, to take the
focused window out of the layout. The other windows close the gap. The same command puts it
back, and it rejoins the layout like a newly opened window.

Your choice wins over the rules. If a rule floats an app and you press the shortcut on one of
its windows, that window is tiled.

Windows you floated by hand are remembered when Iguana restarts, and so are windows you
tiled by hand against a rule. After a restart of the Mac, such a window is floated or tiled
again if it comes back in the first three minutes with the same title. A floated window is
also known again without its title when it was the only window its app had.

## Place a floating window from the keyboard

The [`place`](/reference/commands/#place) command puts the focused window in a part of its
display: a half, a quarter, the middle or all of it. It uses the same area as the tiled
windows, inside the [gaps](/reference/configuration/#gaps). A tiled window is floated first.

```text
place center|left|right|top|bottom|top-left|top-right|bottom-left|bottom-right|full
```

`center` keeps the window's size. `full` fills the area, and the window stays floating:
[`zoom`](/reference/commands/#zoom) is the command for a tiled window.

There are no default shortcuts for `place`. Add the ones you want to
[`[bindings]`](/reference/configuration/#bindings), for example:

```toml title="iguana.toml"
[bindings]
option-c = "place center"
option-ctrl-left = "place left"
option-ctrl-right = "place right"
option-ctrl-up = "place top"
option-ctrl-down = "place bottom"
option-ctrl-u = "place top-left"
option-ctrl-i = "place top-right"
option-ctrl-n = "place bottom-left"
option-ctrl-m = "place bottom-right"
option-ctrl-return = "place full"
```

Some apps will not let a window get smaller than a minimum size, or change its size at all.
Such a window still goes against the same edges: with `place left` its left edge is on the
left of the screen.

## Rules

A rule says what happens to the windows that match it: whether they float, where the floating
ones open, and which desktop or display they are sent to when they first appear. Rules live in the
[config file](/reference/configuration/#rule) as `[[rule]]` sections, and in the
**Window Rules** pane of the [settings window](/guides/settings-window/#window-rules).

Each rule has up to seven keys:

| Key | Type | Meaning |
| --- | --- | --- |
| `app` | string | A bundle identifier, matched exactly, or part of the app's name. Case is ignored. |
| `title` | string | A regular expression matched against the window title. Case is ignored. |
| `float` | boolean | `true` floats matching windows. `false` makes the rule an exception: matching windows are tiled. Defaults to `true` in a rule without `desktop` or `display`. |
| `desktop` | whole number, 1 to 16 | Sends a matching window to that desktop when it first appears. See [Send an app's windows to a desktop](#send-an-apps-windows-to-a-desktop). |
| `display` | string, or whole number 1 to 16 | Moves a matching window to that display when it first appears: part of the display's name, or its number from the left. See [Open an app's windows on a display](/guides/desktops-and-displays/#open-an-apps-windows-on-a-display). |
| `size` | two numbers, 100 to 10000 | The width and height a floating window opens at. See [Size and place an app's windows](#size-and-place-an-apps-windows). |
| `position` | string | Where a floating window opens: any position `place` takes. |

A rule needs `app`, `title` or both. With both, a window must match both.

**The first rule that matches a window decides.** Rules are tried from the top of the file
down, and the first one that matches answers for everything: whether the window floats and
where it is sent. The rules below it are not asked. A window that no rule matches is tiled and
stays on the desktop it opens on.

<Tabs>
	<TabItem label="By bundle identifier">
		```toml title="iguana.toml"
		[[rule]]
		app = "com.apple.calculator"
		float = true
		```

		The most precise form. It matches only that app.
	</TabItem>
	<TabItem label="By app name">
		```toml title="iguana.toml"
		[[rule]]
		app = "calc"
		```

		Matches every app whose name contains "calc". Convenient, but check that it does not
		catch more than you meant.
	</TabItem>
	<TabItem label="By window title">
		```toml title="iguana.toml"
		[[rule]]
		title = "^Preferences$"
		```

		Matches a window whose title is exactly "Preferences", in any app.
	</TabItem>
	<TabItem label="App and title">
		```toml title="iguana.toml"
		[[rule]]
		app = "Finder"
		title = "Info$"
		```

		Matches Finder windows whose title ends in "Info".
	</TabItem>
</Tabs>

The app names and titles above are examples of the syntax. Use `iguana list-windows` to see
the real app name and title of a window you want to match.

To find an app's bundle identifier:

```sh
osascript -e 'id of app "Calculator"'
```

### The built-in rules

With no rules of your own, Iguana floats three apps:

| App | Bundle identifier |
| --- | --- |
| System Settings | `com.apple.systempreferences` |
| Calculator | `com.apple.calculator` |
| Activity Monitor | `com.apple.ActivityMonitor` |

<Aside type="caution" title="Rules replace the built-in list">
Rules are the one part of the config file that is not merged with the defaults. As soon as
your file has any `[[rule]]`, it lists all the rules. If you want to keep the three built-in
rules, keep them in the file. `iguana config init` writes them out for you.
</Aside>

### Exceptions

Because the first matching rule decides, a rule with `float = false` can carve an exception
out of a more general rule. Put the exception above the rule it is an exception to.

```toml title="iguana.toml"
# Safari's windows float, except those whose title contains "Downloads".
[[rule]]
app = "com.apple.Safari"
title = "Downloads"
float = false

[[rule]]
app = "com.apple.Safari"
float = true
```

The app and the title here are an example. The other way round, with the general rule
first, the exception would never be reached.

Create exceptions in the config file, where you can see their order. The Window Rules pane
of the settings window shows an exception with a "Tiled, as an exception" label and its Float
switch off, and keeps it as one when you change other rules there.

### Send an app's windows to a desktop

Give a rule a `desktop` and a window that matches it is sent to that desktop when it opens.
You stay on the desktop you are on.

```toml title="iguana.toml"
# Slack's windows open on desktop 3 and are tiled there.
[[rule]]
app = "com.tinyspeck.slackmacgap"
desktop = 3

# Music floats, on desktop 2.
[[rule]]
app = "com.apple.Music"
float = true
desktop = 2
```

A rule with only `desktop` says nothing about floating. Its windows are tiled like any other
window, and its dialogs float on their own. Add `float = true` to float them as well.

Because the first matching rule answers for everything, a window gets its floating and its
desktop from the same rule. If Slack is matched by a `desktop` rule, a float rule further
down that also matches Slack does nothing for it. Put both keys in one rule instead.

The window is sent once, when it opens. After that it is yours to move.
[Desktops and displays](/guides/desktops-and-displays/#open-an-apps-windows-on-a-desktop)
says exactly when a window is sent and when it is left alone.

### Size and place an app's windows

A rule that floats its windows can also say where they open, with `size` and `position`.

```toml title="iguana.toml"
# Calculator opens in the middle of the screen, 400 by 600 points.
[[rule]]
app = "com.apple.calculator"
float = true
size = [400, 600]
position = "center"

# Notes opens in the right half.
[[rule]]
app = "com.apple.Notes"
float = true
position = "right"
```

- `size` is the width and the height in points, each from 100 to 10000. On its own it keeps
  the window's top-left corner where the app put it, moved in if the window would not fit.
- `position` is any position the [`place`](#place-a-floating-window-from-the-keyboard)
  command takes. On its own, `"center"` keeps the window's size.
- With both, the window is given the size first and then put in its position. The halves,
  the quarters and `"full"` have a size of their own, so they ignore `size`.

As with `desktop`, a window is placed once, when it opens while Iguana is running. Windows that
are already open stay where they are, also when you reload the config, and nothing is placed
while tiling is paused. Dialogs and sheets are never moved.

`size` and `position` only apply to windows the rule floats. In a rule with `float = false`,
or with only `desktop`, they do nothing and Iguana warns about them. The Window Rules pane of
the settings window has no controls for them, and keeps them as they are when you change a
rule there.

A `display` works the same way for a display, and its windows go onto the desktop that
display is showing. With both keys in one rule, the desktop decides. See
[Open an app's windows on a display](/guides/desktops-and-displays/#open-an-apps-windows-on-a-display).

### No rules at all

Leaving every `[[rule]]` out of the file does not mean "no rules": the built-in ones apply.
To float nothing by rule, say so with an empty list, above the first table in the file:

```toml title="~/.config/iguana/iguana.toml"
rule = []
```

Removing the last rule in the settings window writes this line for you.

### When rules are checked

A rule is checked when a window first appears. Whether a window floats is checked again for
every window when the config is reloaded. A window whose title changes later is not checked
again until then.

The desktop, the display, the size and the position are different: they only count at the moment
a window opens. Reloading the config never moves a window that is already open.
[`apply-rules`](/reference/commands/#apply-rules) does: it sends every open window to the
desktop or display its rule names, and decides floating again as a reload does.

A rule that has neither `app` nor `title`, whose `title` is not a valid regular expression,
or whose `desktop` is not a whole number from 1 to 16, is skipped with a warning. The other
rules still apply. A `display`, `size` or `position` that is wrong is ignored with a warning,
and the rest of its rule applies.
